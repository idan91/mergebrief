# Entry comment

- **Entry-comment draft gate:** the Entry comment posts on draft PRs unless `.mergebrief/settings.yaml` sets `entryCommentOnDrafts: false`; the delete-only sweep runs ONLY on that explicit off (a settings fetch failure suppresses posting on a draft but never deletes a live comment).
- **One Entry comment per PR:** every write of the PR row's Entry id is a compare-and-set from the id the run last saw (`swapEntryComment`). A post whose swap loses deletes the comment it just made, best-effort, then tracks the row's id as live but not as its own, and deletes it only after a fresh head read confirms its own head (a moved head leaves it, a failed read leaves it to the head's sync). The winner's body may be stale, so a terminal post or a sync that loses its swap, or finds the row tracking a comment it never read, queues the head's sync, which renders the Entry again from the head, the row and the stored brief read fresh; a sync that finds its body live queues nothing more. A sweep whose clear loses leaves the winner's id. A post tells which live body it may replace by the marker and the hidden kind token after it, which carries the head's sha (`isHeadEntryBody`, `isOnDemandEntryBody`), never by the body's text, whose copy, rev link and reset time vary; a marked body with no readable token is unsettled and names no head, so the next write that replaces an unsettled body rewrites it; the closed body is replaced only by a post that read the PR open or by the sync's ready body over that head's stored brief, and an unmarked body is left. Every Entry body ends in a hidden marker, and each tracked post lists the PR's comments and deletes the marked ones older than it by the same author: what a run killed between its post and its swap left. A newer marked comment is a later run's mid-swap and stays.
- **The failed Entry is terminal-only:** a run that ends `failed` with no retry to follow (permanent, graphile's last attempt, or the head's claims spent) posts the failed body, built from the code alone, never `params.detail`. Under the Entry gate it replaces this head's generating, capped or earlier failed body, on a head it read as current the on-demand body and the closed body a reopen outdated too, or creates the comment while the PR row names none another run posted, and leaves every other live body; a stored brief keeps its ready body. Every Entry post after the PR read first reads the head: a moved head leaves the thread to the newer head's run. On an unread head the generating, ready and failed posts only replace a live body that names this head, the capped and on-demand posts stand down, and the run goes on. A run that failed before reading the PR knows no gate, so it only replaces this head's own bodies. A retrying failure, a lost claim, supersession, the cap and shutdown post nothing, and a comment error only warns. Ahead of any write that ends a run `failed` (an exhausted claim's own, in its transaction), and after a ready, on-demand, capped or failed post that GitHub failed in a way a retry may clear, that lost its swap, or that stood down on an unread head (a ready post also on a draft's closed Entry gate), the run queues the head's Entry sync (`sync-entry`, keyed per head, ten attempts on graphile's backoff); the api queues it as well when a PR with a tracked Entry comment closes. The sync renders the Entry from the row through the same compare-and-set: the ready body over a stored brief for the head (on an open PR one at the current base, the run's own test, so a retargeted head's failure keeps its failed body; on a closed one at any base), the closed body (replace-only) on a closed or merged PR, else the failed, on-demand or capped body the row names, the capped one recreated only where the PR row still tracks a comment; a pending, running or superseded row, or on an open PR a moved head, leaves the thread. On an open PR whose head it read as this one, the ready, on-demand and capped bodies replace any marked body, as the run's own posts do; the failed body replaces only what the failed post does, so an older head's ready Entry stays. A closed or merged PR renders GitHub's last head and replaces any head's generating, failed, capped or on-demand body, since a PR closed inside the debounce window gets no later run; over a stored brief its ready body also replaces that head's closed body, which a close sync posts while the run still generates. Nothing it posts creates a comment on a PR that is no longer open. A failure a retry may clear throws for graphile's retry, a draft's unreadable `settings.yaml` included (the run's own post stands down there; the sync exists to land it), and the last attempt logs `job.retries.exhausted`; a refusal for good (a 401, 403 or 404 write, a row outside the scope) ends the sync with a warn. A sync that cannot queue its successor throws for graphile's retry.
