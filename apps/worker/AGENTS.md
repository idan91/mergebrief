# apps/worker — agent notes

The long-lived background worker. Drains graphile-worker's `generate` jobs — the ones `persistence`'s `createIngestRoutines` enqueues — and produces the PR's artifacts: shared Brief, comparison marks, carry-over hunk spans, revision narrative, and pre-warmed delta cores (one per distinct checkpoint SHA, huge-span skip honored). The generation engine is `brief-core`, reused as-is behind its `Generator` port.

Repo-wide conventions apply (root AGENTS.md); refinements below.

## Map

**Entry points: `src/index.ts`** (the public surface, `exports["."]` — tests + future embedding) and **`src/main.ts`** (the runnable startup wiring, `pnpm start` — deliberately not exported).

What the layout can't show:

- `task/generate/` is the job, and `createRecoverGenerationTask` its lease recovery over the same run. `index.ts` orchestrates: open the run, decide it once, then brief → ready Entry → revision artifacts → delta cores → finish, settling supersession, shutdown and failure in one catch; `types.ts`, `consts.ts` and `utils.ts` hold its shapes (`RunContext`, the per-run value built once; `RunDecision`), tokens and pure helpers. `logic/` holds the steps, the run steps taking the `RunContext`, the rest the payload and an inputs record: `run-context` (row guards, source, first GitHub read, the url-box successor schedule), `run-decision` (stored brief, fresh, capped or stand-down; the only caller of the spend gate), `run-inputs` (files, diff, metadata, repo config, the Entry gate), `run-artifacts` (brief, revision and delta artifacts, finish), `ready-entry` (the ready Entry, and the one a capped stored-brief run owes), `job-failure` (mark failed, the job.fail and retries-exhausted events), `spend-gate` (the daily cap and the row claim, one transaction; a stored-brief run's charge at its first paid call), `claim-recovery` (the recovery job's claim check and its scheduling), `supersession-watch` (the abort controller, head polls and lease renewal), `errors` (permanent vs transient classification, the provider.error event, the timed generator call), `pr-metadata` (the envelope and the row's stack record), `ticket-context` (the memoized tracker read), `entry-comment-gate` (draft opt-in and the delete-only sweep), `entry-comment-manager` (the four operations over one live comment id; body builders stay in `task/entry-comment.ts`), `brief-generation` (fresh brief: `anchor-decision` for whether to anchor and `anchored-run` for the previous-brief input and its hop write, then brief-core's `generateBrief` and the write; plus the skip path's retry-resume), `revision-artifacts` (marks + narrative), `checkpoint-deltas` (one core per checkpoint SHA), `artifact-check` (the warn-only write check and the risk names it accepts) and `model-span` (one GenAI span per generator call, with token usage, wrapped around the run's generator; the run's steps get `step-span`'s `traceRunStep`, which leaves a span unfailed when the run ended by design or its watch or shutdown aborted it).
- `task/github-port.ts` is the GitHub boundary: `PullRequestSource`, the PR-bound reads a job makes, over `packages/github`'s bindings (`GitHubBinders`; `main.ts` passes the App's, tests the `github/testing` fake). An installation job reads through `bindInstallationGitHub` and alone carries `entryComments`. A url-box job reads through `bindReviewerGitHub` on the grant-resolved viewer token, with no renewal; one probe decides the whole job, and a 404/403 switches every read to `bindOperatorGitHub` on the operator PAT. The PAT comes from `packages/github`'s config, and `main.ts` awaits its owner lookup before the runner starts; the switch opens only when the payload's `owner_user_id` owns the PAT, otherwise the job runs as if no PAT were set. A denied probe while the lookup is still pending throws transient (`github-unavailable`) so graphile retries. On the PAT the open-PR list answers empty, so the brief resolves no stack: that list names every PR in a repository the owner cannot see. A ticket in another repository answers not-found unsent, so the PAT reads no issue outside the job's repository.
- `runner.ts` owns boot order (app-schema → queue-schema migrations) and the long-lived graphile runner.

## Invariants (enforced, don't weaken)

- **Payload handshake:** the job payload shape is the shared `GenerateJobPayload` union in `types` — string ids, snake_case. An App-installation job carries `installation_id`; a url-box job carries `owner_user_id` + `grant_id` (a credential REFERENCE — never token material). Task ids come from `types`' `QueueTasks`. The shape changes additively, per the rule on `GenerateJobPayload`: a queued job outlives the release that wrote it, so the parser (`src/task/payload.ts`) takes a new field as optional, and the compile-time pin there breaks the build when the parser requires a field the contract does not guarantee. It cannot see jobs already queued, so review holds the additive rule. The optional `traceparent` is read apart from the job's fields (`readPayloadTraceparent`), so a bad one costs the span link, never the job; every task `buildTaskList` registers runs through `traceJob`, one root OTel span per job linked to the enqueue.
- **Tenancy:** everything goes through persistence's ctx-bound interfaces (`createTenantRepository`, `createArtifactStore`, `createGenerationProjection`); the scope identity (installation or url-box owner) enters ONLY via the validated payload — never a spoofable source.
- **Url-box jobs never write to GitHub:** the Entry-comment surface is off entirely for them, and the viewer token is used for reads only — decrypted lazily per job, held in the bound source's closure, never persisted or logged.
- **Abort is not a failure**: supersession → terminal `superseded`, `attempts` untouched, NO graphile retry, no salvage/dump.
- **No double-spend:** brief and delta cores are skip-if-stored; marks and narratives are content-addressed upserts. A retry pays only for what a prior attempt didn't finish.
- **Write checks are warn-only:** each Brief, Delta Brief and Revision narrative runs its `brief-core/artifact` write check before the write (`logic/artifact-check`); a failure logs `artifact.check.fail` with `kind` (a `GenerationKinds` value, as on `generation.complete`), `issueCount`, `firstPath` and the generated body is written unchanged. A Brief's check accepts this run's custom risk names plus the tokens on its carried chunks. Stored Briefs are read back only through `readStoredBrief`; an issue's `message` is never a log field.
- **Error classification:** permanent failures (404/406, deterministic generation failures, persistence's `ScopeViolationError` and `InvalidArtifactBodyError`) are marked `failed` and NOT rethrown; transient ones (429/5xx/network) are marked and rethrown so graphile owns retry/backoff. `logic/job-failure.ts` reads the thrown class once and decides the retry.
- **`main.ts` is the composition root and the only reader of `process.env`** besides `instrument.ts`, the telemetry preload (`--import` ahead of `main.ts` in `pnpm start` and the image), which reads the `OTEL_*` config only and starts `logging/tracing`; `main.ts` stops it after the pool closes; everything else takes `env` or its values as parameters (`loadConfig(env)`, which also parses `WORKER_CONCURRENCY`, the runner's slot count, default 1, and `REVISION_NARRATIVE_ENABLED` and `HUGE_SPAN_RATIO`, refusing boot on a bad value), brief-core's helpers included. The generator block comes from the instance config (`MERGEBRIEF_CONFIG` → `mergebrief.config.yaml`, else zero-config defaults); BYOK keys resolve by env-var NAME (`generator.apiKeyEnv`) — never from DB or repo config. The tracker root is built there too (`GenerateTaskDeps.trackerRoot`: the env and the `contextSources:` block, tokens by env-var NAME) after `checkConfiguredTrackerReads` refuses boot on a listed tracker it cannot read; the task binds GitHub's transport per job, offers Notion's only to installation jobs, and resolves one read per bound slot when a core needs the ticket.
- **Repo-config is fail-open:** nothing in the `.mergebrief/` phase may fail a generation — fetch failures become loud `fetch-failed` outcomes, invalid files are rejected whole, and an unexpected crash degrades to no-config. Per-file outcomes are recorded on the generation row BEFORE the model call; the policy snapshot rides the brief artifact.
- **Entry-comment draft gate:** the Entry comment stays off draft PRs unless `.mergebrief/settings.yaml` opts in; the delete-only sweep runs ONLY on known-off settings (a settings fetch failure suppresses posting but never deletes a live comment).
- **The daily generation cap gates ONE boundary**: `applySpendGate` claims the row through `projection.claimRun` before any provider call, so a run never counts itself. The gate sits after the GitHub read and the brief lookup: a job whose base and head pair already has a stored brief takes no claim while no claim names its row (a claim live or lapsed sends it through `claimRun`, where it is `held` or takes the lapsed claim), counts only if it pays (its first provider call is charged under the cap lock through `chargeRun`; refused there, it logs `spend.cap.trip` and stands down without a row write), and on success settles a row no run holds through `settleStoredBrief`. A run that finds its row `succeeded` marks it neither `failed` nor `superseded`, from the first read on. Such a run may still owe a checkpoint delta or a narrative, so at the cap a count-only check refuses it before any provider call. A run ingest did not project (the live base moved past the stored one) projects itself before the gate.
  - `claimRun` counts attempts started this UTC day across the instance under one advisory lock, then claims the row with a run id and a 2-minute lease, renewed on the 20s head-poll tick (the pre-call head checks do not renew). Only a claim records an attempt, a graphile retry's included; `held`, `finished`, `capped` and `exhausted` record none. A head takes at most 3 claims between triggers (`generation.claims`, reset when a trigger re-projects it); the fourth is `exhausted`, logs `job.retries.exhausted` and ends the row `failed` as `attempts-exhausted` (an earlier failure stays), or settles it when the brief is stored; the job ends without a retry. Every later row write is fenced by the run id; `held` and `finished` leave the row untouched, and `held` re-queues the job for after the lease (`requeueGenerateJob`) before this one completes; a held recovery run moves its own job instead. A claim queues the head's `recover-generation` job for after the lease in the claim's own transaction (one pending per head). Every attempt reads the claim: a live lease moves the job past it (`scheduleClaimRecovery`), a lapsed one is taken over, and an unclaimed row is a no-op on a first attempt and a rerun on a retry. A recovery run claims the row even over a stored brief, and its claim queues no further recovery: the same key would end its own retries. Check failures settle through the same failure path as a run. The dead holder's own job stays locked; graphile frees it only after 4 hours, and any `add_job` on its key before then (a later trigger, a held run's re-queue) detaches it with its attempts spent, so it may never run; if it does, the attempt budget and the stored-brief path bound what it can pay. A lost claim, seen by the tick, by a fenced write, or by the claim itself on a row whose pull request was deleted, stands down without a write or a retry; shutdown releases the claim, which still counts. A shutdown release and a recovery takeover that made no provider call each log a `warn` with `attempt` and `maxAttempts`.
  - At cap the run is SKIPPED — terminal `capped` (not `failed`, no retry, no attempt consumed), `evt: spend.cap.trip` at warn. The Entry comment is UPDATED only if one exists and no brief is stored for the pair, never created; a row already marked `failed` keeps that status. `spend.maxGenerationsPerDay` is one number and `spend.cap.trip` still carries `repo`.
- **Scheduled jobs are instance-wide and worker-only**: each runs on graphile's cron (its `*_CRONTAB` line joined into the runner's `crontab` in `main.ts`) and calls a persistence sweep that takes the handle, never a ctx. Nothing on a request path may call one.
  - `sweep-audit` (daily) calls `sweepAuditLog`; retention is an operator env setting. Unset retention deletes nothing; a window under the 30-day floor is refused.
  - `sweep-sessions` (hourly) calls `sweepExpiredSessions`, always on: an expired session grants nothing.
  - `sweep-pull-requests` (daily) calls `sweepClosedPullRequests`; retention is `PR_RETENTION_DAYS`, read by close time across both scope worlds. Unset retention deletes nothing; a window under one day is refused.
- **Migrations at boot are idempotent** and ordered app-schema → queue-schema (`startWorker`); the `graphile_worker` schema stays graphile-owned.
- **One process logger**: `main.ts` builds it; the task takes it via `GenerateTaskDeps.log` and stamps `{prId, headSha}` child bindings on every job line; graphile lifecycle logs ride `createGraphileLogFactory`.
  - The first-class `evt` names minted here — `job.fail`, `job.retries.exhausted` (`attempts === max_attempts`, or a head's claims spent), `provider.error`, `spend.cap.trip`, `artifact.check.fail` — come ONLY from the taxonomy table in `docs/self-host/observability.md`.
  - JOB/PROVIDER failure logs are MESSAGE-ONLY (no `err` field): provider cause chains may carry request contents, and the URL scrub targets URL-shaped secrets, not prompt/diff payloads. Boot failures (`main.ts` catch) are exempt — nothing provider-shaped reaches them, and the `err` field keeps the stack the operator needs.

## Tests

`test/sweep-audit.test.ts`, `test/sweep-sessions.test.ts` and `test/sweep-pull-requests.test.ts` drive the scheduled sweeps over the same PGlite harness.

`test/generate/` = integration, one file per behaviour, via `persistence/testing`'s PGlite harness (real migrations + the graphile_worker stub), a stub `Generator` (canned outputs parsed through the request's own schema — no model calls), and `github/testing`'s fake GitHub behind the real port (no network; url-box jobs seed a real grant). The shared `helpers.ts` holds the stubs, the fake's PR #7 arrangement, `setUpHarness` and `makeTask` (the task over the test's harness with stub defaults; a test passes only what it varies). An interleaving the fake cannot arrange wraps the binding a job reads through (`interceptInstallationRepo`). `trigger` drives the real `createIngestRoutines` enqueue and feeds the task the payload read back from the stubbed jobs table.

`test/graphile-claim.test.ts` is the handshake's contract test: real graphile on `MERGEBRIEF_TEST_POSTGRES_URL` claims the job persistence enqueued through the worker's own `buildTaskList` (`src/task-list.ts`, which `main.ts` registers), and the payload passes `parseGeneratePayload`. It skips locally without the URL and fails under `CI`.
