# apps/web: agent notes

The TanStack Start front end: the DB-backed read + submit surface, fed by `apps/api` for both App-installation and URL-box briefs.

Repo-wide conventions apply (root AGENTS.md); refinements below.

## Conventions

- Server data crosses `data/request`: one named function per operation over `request` / `requestText`, which read method and path from the contract's operation table. `data/apiFetch` is the transport underneath (isomorphic: SSR forwards the viewer's cookie to the API over HTTP, through the SAME authz gate); only a route outside the table, or a caller that reads the raw response (the upload's `Retry-After`), calls it directly. Never reach persistence from a server function: that would be a second enforcement path. Components and query builders call the named function, never `request`. A `build*QueryOptions` builder infers its return, as a facade does: the inferred type carries the query-key tag `setQueryData` and `useQuery` read back. A read returns `request(id, { params }, schema)` and throws `ApiError`; a write calls `request` in a `try` and maps the caught error through `readFailureKind` and a partial kind table with a `fallback`: a 401 comes back as the shared `WriteFailureKinds.UNAUTHORIZED` unless the table names it, and a network throw or 504 as `INDETERMINATE`.
- **JSON from the API or storage parses through a zod schema.** The schema lives in the owning feature's `schemas.ts`; a one-off guard private to a single operation stays beside it. A read over `request` hands it the schema directly; a `parse*` wrapper exists only for a caller that parses outside `request`, and calls `parseWithSchema` (`utils/parse-with-schema`). The exported type stays a hand-written interface, and the test pins `Equals<z.output<typeof schema>, Interface>`; a transform returns its literal `satisfies Interface`, never an annotated return, or the pin compares the interface with itself. Optional fields are `.exactOptional()` and `.readonly()` matches the interface. A wire `null` the interface keeps absent goes through `dropNullKeys`, and an optional field whose bad value must drop rather than fail its object goes through `dropInvalidKeys` (`utils/drop-keys`); each wraps a plain object schema or the other helper's result, so `.readonly()` and a union wrap the helper, never the reverse. A REQUIRED closed-vocabulary field, or an optional one whose absence carries a default meaning, reads through `buildOpenEnumSchema(Map)` (`utils/open-enum`), so a member this bundle predates reads as `UnknownValues.UNKNOWN` and the interface widens the field with `UnknownValue`; every renderer of such a field gives `unknown` a neutral rendering (`packages/contract/AGENTS.md`, Reader tolerance). URL search params and text grammars (diffs, markdown, headers) stay hand-written.
- **Error components render a curated mapper** (`briefErrorDetail` / `prBriefErrorDetail`), NEVER `error.message`: even an `ApiError`'s embeds the request path. Messages reflecting caller input (a pasted URL) are curated too: they land in a `role="alert"`.
- Copy: every `.ts` and `.tsx` literal that is sentence-shaped or Capitalised lives in the `packages/i18n` catalog; the copy lint holds it in `all` mode, and `house/no-shout-case-copy` holds the SHOUT_CASE consts i18next skips. A component reads `useTranslation()`; a pure helper takes a `TFunction` first parameter; a data structure stores a `TranslationKey` and resolves at render. The wire carries a code, never a sentence.
- `.oxlintrc.json` exempts the copy that stays English by shape: the receipt (`features/review/utils/receipt.ts`, frozen English shown in the submit flow and never posted to GitHub; its counts ride on the signature line), the review body `features/review/utils/submit.ts` posts to GitHub (the signature line and the fold preamble), head meta (`routes/__root.tsx`), and the dev fixtures (`features/brief/test-utils/fixtures.ts`, `features/inbox/test-utils.ts`, `**/characterization/**`). Repo-authored strings passed through verbatim (`criteria`/`implication`) stay English too.
- Isomorphic and shared client/server modules INJECT their log sink (a narrow `{ warn }`/`{ error }` interface `packages/logging`'s `Logger` satisfies); they never import `server/logger` (`server-only`). No sink = silent, which is correct client-side only (a browser has no operator). EVERY server-side caller passes one; `data/ssrWarnSink`'s `getSsrWarnSink()` is the resolver for call sites that run on both sides. Forgetting it is silent by construction: a review checkpoint, not a lint error.
- **Security headers ride two seams.** `src/server.ts` stamps `contract`'s `SECURITY_RESPONSE_HEADERS` on all it answers, proxied `/api` included, and `server/serve` stamps what never reaches it (client files, host and method refusals). A header already on the response wins. The demo build has no listener: its static host owns its headers.
- **Hoist singleton accessors** (`getServerLogger()` and kin): assign once at module scope, or once per composition function, and use the const at every call site. Deferring construction is only justified when the accessor cannot do its own env lookup internally (the `ssrWarnSink` isomorphic path stays lazy by design).
- Composition root: `src/server/env.ts` is the one `process.env` reader, and `src/server/logger.ts` and `src/server/api/transport.ts` are the sanctioned process singletons built from it. `src/serve.ts` is the production process (`docker-entrypoint.sh web`): srvx over `dist/`, with the host check and the shutdown drain in `src/server/serve/`. `src/instrument.ts` is its telemetry preload (`--import` ahead of `serve.ts`), which starts `logging/tracing` from the `OTEL_*` config; `vite dev` runs without it. `vite preview` is never the production server. This tier holds NO credentials and no database: `/api/*` is proxied to the API process, and SSR reaches it through the same transport so a render meets the same authorization the browser would.
- **Decompose at birth, not on review.** Every sub-component gets its own nested folder plus `module.scss`. Prop interfaces are exported (`interface XProps`) and declared in the component file, never inline in the signature; a lone `XProps` stays there. A function or const inside a component or facade stays there only when it closes over its state; anything that can take its inputs as arguments goes to a co-located `utils.ts`/`consts.ts` with a co-located unit test. A `types.ts` is for non-prop types a file would otherwise grow: shared unions, maps several files need, or a discriminated prop shape that depends on a base type.
- **Never gate behaviour on how a visually identical mode was entered.** If two states look the same, a behavioural difference between them is indistinguishable from a bug. Key behaviour on the visible state, or make the modes visibly distinct. When the same defect is reported a third time after two verified fixes, question the design rather than the code.
- **Fold capability into the shared component; no behaviour wrappers.** A generic capability (positioning, hover, anchoring) belongs in the component's own API. `HoverX`/`AnchoredX`/`XWrapper` forks its identity. A wrapper is only justified when it encodes a product feature's domain mapping.
- **One `.svg` asset file per mark or icon**, imported via svgr. Never a collection of path data grouped into one `.tsx`.
- **Every interactive change declares its accessibility contract** before review, not during: where focus lands, how async outcomes are announced, targets ≥ 24px.
- **Client code may `console.error` on unexpected failure**; the user sees the failure via UI state, never a raw message.
- **The version notice is one feature folder** (`features/version`): the band under the Header on Home and the brief page, the per-user dismissal, and the Account menu's dismissed row and avatar dot all read one query (`buildVersionQueryOptions` over `GET /api/version`); the menu's row and dot go through `useVersionPresence`. A security release has no dismiss; a `dev` server never shows it, so the browser suite cannot see it and the local arm in `docs/dev/pre-release-testing.md` is how it is exercised.

## Hooks and JSX

- **One facade per component.** A component carrying heavy logic gets one co-located `use<Component>Facade` hook (`useAttributedGroupCardFacade` is the template) and stays thin: the component wires props in and moves JSX into subcomponents; the facade owns flow state (pending, error, copy), store subscriptions, flow actions and derived selection. A facade's return is inferred from the object it returns, never a `*FacadeReturn` type; any other exported hook returning an object names its return type. Splitting a facade does not make more facades: the pieces are named for their job (`useReading`, `useViewLayout`), never `use*Facade`, never in a `facade/` folder. A piece lives by usage: the concern folder it serves, else a `hooks/` folder beside the component, else promoted by the co-location rule.
- **A function is a hook only if it calls one.** A `useMemo` body that only computes is a pure function in `utils.ts` with a test, and the hook keeps the one-line memo.
- Memoize (`useMemo`, `useCallback`, `memo`) only for a measured cost or a contract-visible need such as a stable dependency a child effect keys on.
- No spread inside JSX, except a primitive forwarding its rest props to its own DOM element, or a floating-ui prop bundle (`getReferenceProps`, `getFloatingProps`, `getItemProps`) onto the element floating-ui positions or the primitive that forwards it: that bundle is the library's contract and has no stable member list to destructure.
- Nothing computed inside JSX: a derived value gets a named const above the return, or moves to the facade or `utils.ts`. Rendering a ready list (`{rows.map((row) => <Row key={row.id} row={row} />)}`) is not computing; filtering, sorting or arithmetic on it is.
- A default prop value is a stable reference. Primitives inline; an object or array default is a module-level const, never a fresh `[]` or `{}` in the signature. A literal default is a new identity on every parent render, so every consumer of that prop re-renders and any memo keyed on it is dead.
- No `render`-prefixed function outside test files; a `renderX` helper is a sub-component.
- An effect syncs React with something outside it. It is idempotent, its dependency list is real, and derived state never lives in one.
- **Each kind of state has one home.** View state a link should reproduce (the revision, the address inside the Brief, the open thread, the conversation filter) lives in URL search params, parsed by the route's `validateSearch` (`features/pulls/search`). Server data lives in the TanStack Query cache behind a `build*QueryOptions` builder. Client state several components share lives in a zustand store; state one component owns is `useState`. A value that must survive a reload lives in localStorage only through its own storage module (`BriefView/Sidebar/storage.ts` is the template: a zod parse on read, a default when the key is absent or storage throws); one the server must render with lives in a cookie the same way (`BriefView/diff-view/diff-view-storage.ts`).
- A flow whose state is more than two coupled fields is one union-typed field moved only by named pure transitions in `utils.ts` (the review flow's `ComposerState` is the template), never a generic `reduce(state, event)`; an async step carries a token, and its settle applies only while that token is current.
- **State that resets on a Brief switch resets one of three ways**: a per-Brief zustand store a `useCreate*` hook holds in a ref and rebuilds when the Brief id changes (`BriefView/store.ts` is the template; the expansion, reading-position and review-flow stores follow it); a `key` on the Brief id for one region's own state; or a value tagged with its Brief id and compared at read. Never a module singleton, a keyed remount of the whole view, or a render-phase reset.

## Placement and styling

- Every folder answers at a glance: one visible MAIN entry, everything else in a visible support category. A feature root = `index.tsx` (THE entry: the component's JSX, or a curated re-export when it has co-located support files), plus `types.ts` and `components/` / `hooks/` / `utils/` / topic folders. Inside `components/`, every component nests under its owning component, and a consumer reaches its support one segment below the folder (`@web/components/Menu/types`). The stylesheet keeps the component name, as the test does (`Menu/Menu.module.scss`). A loose uncategorized file is a defect unless its placement is argued and recorded (`brief/queries.ts`).
- **apps/web runs no server functions for data.** A read or write the app needs is an `apps/api` route reached through `data/request`; a dev-only surface is a dev-only API route. `src/server/` is app-wide infrastructure only (env, logger, API transport, health, the refused paths). Lint bans `createServerFn` in `apps/web/src`.
- The framework reads three `src/` entries by name (TanStack Start defaults): `router.tsx`, `server.ts` and `start.ts`. `start.ts` registers the error serialization adapters (an `ApiError` crosses SSR as its code and status, any other error without its message) and keeps Start's CSRF guard. The router's `defaultErrorComponent` and the root's `errorComponent` are `components/PageError`; the root's document is its `shellComponent`, so that screen renders inside it.
- A feature's internal files import targets directly, never their own feature's index. A barrel never re-exports anything touching `server/` (import-protection breaks the client build).
- **The Brief feature is two layers**, `model/` and `ui/`. `features/brief/model/` and `queries.ts` beside it import no other feature and nothing of `ui/`; `features/brief/ui/` holds the components, the rendering hooks and their modules. Review imports the Brief through `brief/model`, and its tests through `brief/test-utils`; pulls composes `ui/` through the Brief entries; `ui/` never imports pulls. dependency-cruiser holds each edge: `web-brief-model-imports-no-feature`, `web-review-imports-brief-model-only`, `web-pulls-imports-brief-entries-only`, `web-brief-never-imports-pulls`.
- A feature's own test helpers live in its `test-utils/` folder (or a `test-utils.ts(x)` file); only a `*.test.*` file or another test-utils module imports one (`web-test-utils-only-in-tests`). Brief model tests import `brief/test-utils/fixtures` alone, never the index that loads the render helpers.
- The global `src/components`, `src/hooks`, `src/utils`, `src/data` and `src/test` folders never import `src/features`; `src/routes` may import feature indexes. Wanting a deeper import is the promotion signal: co-locate with the single consumer, and on a second consumer promote to the nearest common ancestor (parent component, feature root, then global). Fixtures no single feature owns live in `src/test`; one typed by a feature's model stays in that feature's `test-utils/`, even when other features' tests use it. Anything touching a feature's store or queries never sits above that feature.
- `apps/docs-site/.vitepress/theme/tokens.css` restates the palette in `src/styles/tokens.scss` by hand: a palette change updates it in the same PR, and `styles/docs-site-tokens.test.ts` holds its dark theme to the tokens.
- `components/icons/mergebrief-*.svg`, `public/favicon*`, `public/apple-touch-icon.png` and `public/og-image.png` are committed brand assets with no generator. The favicons, touch icon and share image draw the mark's shape and the brand, ground and Text 1 colours: a change to either redraws them in the same PR. `favicon-16.png` is drawn on whole pixels, never scaled from the mark. apps/docs-site ships byte-identical copies of the favicons and the touch icon: a change lands in both. `utils/share-image` restates `og-image.png`'s 1200x630; its test holds the two equal.
- Zero raw colors/font-sizes/radii/shadows in `.module.scss`: semantic-scale tokens/mixins only (no value-named tokens); off-scale values stay raw behind a line-scoped stylelint disable that names its reason, or earn a component-local token with a one-line justification. Every stylelint disable carries a `-- <reason>`; `reportDescriptionlessDisables` holds it.
- A module declares a custom property only for a value its component alone owns. A job two components share is one mixin, function or token (`mixins.dimmed` for every disabled control, `mixins.user-select`, `mixins.safe-area-bleed`, `functions.inner-radius`, `functions.ink-lift`, `functions.edge-bar` for every inset edge bar, `functions.ring` and `functions.inset-ring` for every ring, `--ring-room`, `--diff-line-box`); a property that only renames a global token is deleted and the token read directly. A module custom property, or a Sass variable outside a `@function`, holds no raw colour (a colour function or hex) and no shadow geometry, written out or routed through `#{}`: `house/custom-property-no-raw-value` (`stylelint-custom-property-no-raw-value.mjs`) holds it in `*.module.scss`, reading every interpolation but a `functions.*` shape builder as a length, and `tokens.scss` is the owner. A value one component alone owns keeps a line-scoped disable naming why. The layout variables (`--header-*`, `--focus-*`, `--sidebar-*`, `--chunk-*`) stay where they are. Popover's panel owns the floating surface (edge, corner, fill, shadow); a consumer sets only its size, padding and layer. Sass keeps a custom property's value as written, so a function call there is interpolated (`--x: #{functions.inner-radius(...)}`); a property whose name is itself interpolated (`#{$edge}: ...` in `mixins.safe-area-bleed`) is parsed as a plain declaration, and Sass evaluates its value.
- State fills: a warning, crimson, green or accent fill over transparent reads a `--color-<state>-tint-<strength>` token at faint 5%, subtle 8%, medium 12% or strong 18%; a fill whose colour varies (`--badge-color`, an added or removed row's `--row-hue`) mixes it at a `--tint-*` strength. An unchanged diff row's 6% Text 1 hover, edges, washes, flashes and surfaces lifted toward a colour stay component-owned.
- Units: text and everything text-coupled is rem via `functions.to-rem(<px>)`: font sizes, touch-target min-heights, measure caps, menu/dialog widths. Chrome stays px: borders, radii, shadows, icon boxes, decorative geometry, breakpoints. Ambiguous sizing → px.
- Spacing: `margin`, `padding`, `gap` and their longhands read a `--space-*` step (2, 4, 6, 8, 10, 12, 14, 16, 24, 32, 48, 64px), `0`, `auto`, or a layout variable (any custom property, or a module-namespaced Sass variable such as `layout.$story-group-gap`), alone or inside `calc()`, `clamp()`, `max()` or `min()`. Stylelint rejects any length literal there in any letter case, any file-local Sass variable (`$pad`, `#{$pad}`), and any `functions.to-rem()` over a number or a file-local variable; percentages, viewport units, `env()` and unitless factors pass. A value within 2px of a step takes the step. One no step holds stays `functions.to-rem(<px>)`, or px when it tracks a border or an icon box, behind `/* stylelint-disable-next-line declaration-property-value-allowed-list -- <reason> */`. A spacing value passed to a mixin is invisible to the rule: a spacing parameter (`layout.wrapping-columns($row-gap)`) takes a `--space-*` step.
- Line height: `line-height` reads a `--line-height-*` step (control 1, display 1.1, heading 1.2, compact 1.35, body 1.5, reading 1.7), a px or rem length such as `functions.to-rem(20px)` for a fixed line box, a custom property, a module-namespaced Sass variable, `inherit` or `0`. Stylelint rejects any other number, a `%` or font-relative unit (`145%`, `1.45em`, `1.5lh`) and any file-local Sass variable (`$lh`, `#{$lh}`). Pick the step by the text's job, not the nearest number.
- Stacking: `z-index` reads `functions.get-z-index("<layer>")`, a name from `$z-layers` in `styles/_functions.scss` (lowest first; a layer resolves to its position times 10), or -1, 0 or 1 inside a component's own stacking context. Stylelint rejects any other value. A new thing that overlaps another takes its own entry where its order needs it; two things share an entry only where they never share a stacking context or never overlap.
- Motion: `transition` and `animation` durations and delays read a `--motion-*` token (fast 120ms, base 180ms, slow 320ms, slide 260ms, spin 700ms, read and flash 1.4s), another custom property or 0. Stylelint rejects any other time literal and any file-local Sass variable (`$dur`, `#{$dur}`) there, and in a `.module.scss` a time literal held in a custom property or Sass variable (`--dur: 300ms`, `$dur: 200ms`); a duration one component alone owns keeps a line-scoped disable naming why (SkeletonRows' 1600ms shine cycle tracks `SHINE_CYCLE_MS`). Hover and colour changes take fast; an entrance takes base and its exit fast, except the focus shortcuts strip, which closes over base as it opens.
- Heading levels follow document structure, never size: one `h1` per screen (a state/error card that replaces the screen owns it), `h2` for a top-level section, overlay content rooted at `h2`, no skipped levels. A component that wants a different size pins one in its own module; a shared shell styles headings level-agnostically so it never dictates a level. Authored markdown through `components/Markdown` is exempt: it keeps its fixed h1→h3/h2→h4 demotion. Reviewer-held: no lint rule expresses it.
- **Styling carries no comments.** A `.module.scss` rule, a token, or a `style` object gets a comment ONLY when a reader who understands CSS could not predict the behaviour: a browser bug or missing feature, a value that must track another file, a cascade trap, or a measured constraint an innocent edit would silently break. Everything else goes: no restating the declaration, no naming the visible layout mechanism, no design rationale, no history. A comment that would survive pasting into another project's stylesheet says nothing about this one.

- `data-testid` for test selection; `data-state`/`data-variant` for styling. CSS targets attributes, not toggled classes. Extracted components adopt both at birth. A behavioral third category (an attribute runtime code queries for) needs an exported constant and its own doc comment, never a bare literal, never doubling as a test or styling hook. Ten exist. `DiffRows` and its `SplitRows` write four, read through `components/DiffRows/consts.ts`: `data-line-origin` through its selectors, `data-line-old` / `data-line-new` through `LINE_ATTRIBUTES`, and `data-line-number` through `EXPANDED_RIGHT_NUMBER_SELECTOR`. `Callout` writes `data-callout` on its floating root, read through `CALLOUT_ROOT_SELECTOR` in `components/Callout/consts.ts`. A `BottomSheet` caller writes `data-sheet-focus` on the control focus lands on, read through `SHEET_FOCUS_SELECTOR` in `components/BottomSheet/consts.ts`. The Brief page's `SubmitReviewCta` and `MarkReadyCta` write `data-terminal-slot`, read through `TERMINAL_SLOT_SELECTOR` in `features/brief/ui/components/BriefView/consts.ts`. `LandscapeRow` and `PhoneBar` write `data-scroll-steering`, read through `SCROLL_STEERING_SELECTOR` in `BriefView/scroll-to-target/engine/consts.ts`. `CollapsibleBar` writes `data-bar-open`, read through `OPEN_BAR_SELECTOR` in `components/CollapsibleBar/consts.ts`. The Sidebar sheet's `ChunkRows` writes `data-chunk-row`, read through `CHUNK_ROW_SELECTOR` in its `consts.ts`.

## Async mutations against external systems (enforced)

Every mutation against GitHub (or any external system) follows these:

- **One write function, one hook.** A write is one named function over `request` plus one hook that owns pending, the re-entry guard, the announcement and the invalidation; a row action calls the same hook a bulk action does, with a one-row selection.
- **Capture inputs at initiation.** Snapshot the ids/values the request ships at click time and, on success, mutate exactly that set. State added or edited mid-flight must never be marked as sent.
- **The external write is the commit point.** Once it succeeds, local persistence is BEST-EFFORT: log failures and keep the success copy. A throw AROUND the write gets INDETERMINATE copy ("may or may not have posted — check GitHub"), never "nothing happened", which invites a double-posting retry.
- **One in-flight request per draft: a disabled button, not a protocol.** The server holds the drafts, so a POSTED one settling after unmount still reconciles on the next read. An AMBIGUOUS failure's warning has no server trace and does not survive leaving mid-post; that window is accepted. Never rebuild a per-tab queue.
- **Result surfaces must outlive the request.** Failure copy also goes through a page-level live region (the toast); an inline `role="alert"` in a closable drawer is inert by the time a slow response lands. Repeat announcements need a DOM change: announce clear-then-set.
- **Server-owned records go read-only locally.** Once posted, a comment's text belongs to GitHub: no Edit/Delete in the UI, and the store no-ops update/delete on submitted comments (a local edit would silently diverge; re-submits ship drafts only). One-shot verdicts are SPENT on success (outcome resets to `comment`).
- **Mirror every deterministic API rejection with recoverable copy** (the contract is `apps/api/AGENTS.md`'s). `submitBlockedReason` mirrors the caps the submit route applies (path length, and the folded body's length, built the way the route builds it over every held draft, the store's `unplacedDrafts` included); keep it in lockstep with `apps/api/src/routes/repos/pr/review/` when either side changes.
- **One operation per user action, and a failure reverts.** Every session write is its own request naming its Brief (`?base=&head=`); there is no snapshot PUT, no batching, no network debounce and no retry machinery: a retry is the action again. A failed write puts the UI back where that same action is still available: the checkbox un-ticks, the composer stays open holding its text. That is why the composer closes on write SUCCESS rather than on click. A `pr-changed-since-read` 409 is terminal for the page, not a per-action failure: it goes read-only behind the revision banner, and nothing drafts locally behind it.

## Test gotchas

- No vitest globals in this repo: `@testing-library/react` does NOT auto-cleanup: add `afterEach(cleanup)` or the previous test's DOM leaks into the next test's `screen` queries. Component/hook tests need the `// @vitest-environment jsdom` pragma.
- Route tests that seed the query cache BYPASS the wire parsers. Pair them with queryFn-level tests against realistic wire bodies; a wrong parser can otherwise ship green.

## Verification

```sh
pnpm -C apps/web typecheck
pnpm -C apps/web test      # characterization harness included
pnpm -C apps/web lint      # stylelint (prettier rides repo-root pnpm lint);
                           # exit code is the judge
pnpm -C apps/web build     # REQUIRED for isomorphic/server-only changes
pnpm -C apps/web test:e2e  # playwright; global setup runs its own postgres container
pnpm -C apps/web perf:fixture && pnpm -C apps/web perf:measure
                           # perf suite; the fixture is generated, never committed
```

`build` is required because TanStack Start's `import-protection` plugin statically denies any CLIENT-graph edge reaching `@tanstack/react-start/server-only`, dynamic `import()` and unreachable `typeof window` branches included, and ONLY `build` fails such a graph (typecheck, test, and lint all pass it). Reach server-only code from an isomorphic module via `createIsomorphicFn().server(...)` with the import inside the branch (`data/apiFetch.ts`, `data/ssrWarnSink.ts` are the templates); a read that must stay synchronous may import statically when only that branch uses the import (`diff-view-storage.ts`).
