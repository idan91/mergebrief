# apps/api: agent notes

The Hono HTTP surface for the self-host backend. Its **webhook trust boundary**, `POST /api/webhooks/github`, verifies the HMAC over the raw body and parses the event through `github`'s Zod boundary. The event then maps, transactionally, to `persistence`'s tenant-scoped writes plus one debounced graphile `generate` job (`createIngestRoutines`).

This app owns its own process. Its composition roots, the only files that read env or construct a database, are `src/main.ts`, `src/migrate.ts` and `src/instrument.ts`; `createApp(deps: AppDeps)` takes everything else injected. Each root loads `apps/api/.env`, then the workspace root's `.env` (`src/boot/env-file.ts`); a value already set is kept, so the shell wins, then the nearer file. With `MERGEBRIEF_CONFIG` unset, `src/main.ts` names the workspace root's `mergebrief.config.yaml` in it when that file exists (`applyDefaultConfigPath`). `src/main.ts` is the startup wiring (`pnpm start`, the compose `api` service), and it serves the top-level `/healthz` and `/readyz` ahead of the `/api` mount. `apps/web` proxies `/api/*` here and holds no credentials. `src/migrate.ts` is the second entry (`pnpm migrate`, `docker compose run --rm api migrate`): it loads only the database and `SERVER_VERSION` through `src/boot/`, then `runMigrate` applies the app schema with auto-migrate forced on and the queue schema, inside persistence's migration lock as boot does (`ensureAppSchema`'s `migrateQueue`), and exits 1 on any config error. Boot's check-only refusal names that command when `MERGEBRIEF_RUNTIME` marks the image, the checkout command otherwise. `src/instrument.ts` is the telemetry composition root: preloaded with `--import` ahead of `main.ts` (`pnpm start`, the image), it reads the `OTEL_*` config only and starts `logging/tracing`; `main.ts` stops it last on shutdown.

Deliberately NOT here: page rendering, and any worker/LLM code. The api imports `brief-core` and `generators` only through their leaf subpaths, never an entry, so the process loads no adapter, dev CLI or provider SDK.

## Topic docs

Topic docs under `apps/api/docs/` bind as firmly as this file. In this file and its topic docs, `docs/dev/`, `docs/self-host/`, `docs/media/`, root files such as `DESIGN.md`, and paths starting `apps/` or `packages/` are the repo root's. Every other path is under `apps/api/`, often written without its `src/` prefix or leading folders; `git ls-files apps/api | grep <path>` finds it.

Before editing a source file, run `git grep -n <file name without extension> -- apps/api/docs` (for an `index.ts`, its folder's name) and read every doc whose hits name your file. Also read any doc whose trigger below names your work:

- **Wire error codes**: touching `shared-errors/` or `error-response.ts`, adding a code (the recipe), or mapping a controller failure or a GitHub denial to a thrown `ApiError`: read `docs/error-codes.md`.
- **Domain layout**: adding a route domain, an operation module, a handler or a controller, or converting a domain: read `docs/domain-layout.md`.
- **Repo gate**: touching `access/` outside `session-layer.ts`, `session-credential.ts` and `instance-access.ts`, adding a route under `/repos/:repoId`, binding GitHub for a route, or touching the operator PAT, the per-PR row world or a mutation's fresh re-resolve: read `docs/repo-gate.md`.
- **Sessions**: touching `access/session-layer.ts`, `access/session-credential.ts`, `access/instance-access.ts` or `routes/auth/`; adding a route that queues a paid run, mints a credential or serves a cookie principal outside `sessionLayer`; touching instance access, the cookie same-origin check, token refresh or rotation, a grant's revoke, or a path that deletes a session or revokes an API token: read `docs/sessions.md`.
- **Operations**: touching `product-operations/` other than `audit.ts`, adding or renaming an operation, or changing a policy field or the refusal order: read `docs/operations.md`.
- **Audit**: touching `product-operations/audit.ts` or the audit stamp in `error-response.ts`, adding a route that acts on a row or collapses a refusal into a 404, or changing what an audit row holds: read `docs/audit.md`.
- **Webhook**: changing `routes/webhook.ts`, an event's ingest or kind, the seen-set or the generate job key: read `docs/webhook.md`.
- **Diff read**: changing `read-diff`, its cache, or the span thread: read `docs/diff-read.md`.
- **Submit**: changing the review submit or post-now flow: read `docs/submit.md`.

## Invariants (enforced, don't weaken)

- **Webhook trust boundary:** the HMAC is checked against the raw body before `JSON.parse`, Zod or any DB touch; an invalid or missing signature is a 401 and nothing is written. The tenant comes only from the signed payload's `installation.id`, never a header (`docs/webhook.md`).
- **Writes go through persistence.** Tenant-scoped writes go through its ctx-bound interfaces (`createTenantRepository`, `createIngestRoutines`, `createPurgeRoutines`, `createLiveReadStore`), and every other write through its own persistence store (sessions, tokens, grants, settings, the webhook seen-set, audit); a route never queries the injected handle directly.
- **New routes owe two checks** (`docs/sessions.md`): one that queues a paid run or mints a credential calls the instance-access check, and a cookie route outside `sessionLayer` proves same-origin as the layer does.
- **A route or middleware throws; it never builds an error body.** Every expected failure exits as a THROW of an `ApiError` subclass (`src/shared-errors/`), sanitized via `onError`. `buildErrorResponse` (`src/error-response.ts`) is the ONE producer of `{ error, code }` bodies, the 1:1 code→status map, the i18n line, the uniform `no-store` posture and the `apiErrorCode` audit stamp; only the `onError` handlers call it (the root's `createErrorHandler` and the product router's). persistence's `ScopeViolationError` renders there as the plain 404 a `NotFound` would, same body, code and audit reason. Non-`ApiError` throws render as sanitized 500s (internals go to the log, never the response). The OAuth callback is the exception: a browser navigation, so every failure redirects home with `SIGN_IN_FAILURE_PARAM` instead of an error body, and a cancel on GitHub redirects to plain `/`.
- **Security headers are set once, at the root.** `stampSecurityHeaders` (`src/security-headers.ts`) adds `contract`'s `SECURITY_RESPONSE_HEADERS` after the handler, only where a route has not set its own, so `ATTACHMENT_RESPONSE_HEADERS` stays stricter. Never stamp them in a route. Health answers are served ahead of the app, on the unpublished port, and carry none.
- **`MergeBrief-Version` rides every response whose session layer resolved a principal.** One middleware at the /api root (`routes/version-header.ts`) stamps the header after the handler whenever a principal is in context, a same-origin refusal included; a session-layer 401, a login redirect, a webhook and the health endpoints carry none, so an unauthenticated caller learns nothing the gated `/api/version` did not already say. Never stamp it in a route.
- **`no-store` on every response of a gated route**, error paths included; it is all per-viewer state (success responses set it explicitly; every error path inherits it from `createErrorHandler`, `src/shared-errors/on-error.ts`, wired via `app.onError`).
- **Every domain route is a catalog operation, and policy is checked at the router seam, not in routes.** The webhook, OAuth, logout, session and version-read routers sit outside the catalog, as `EXEMPT_ENDPOINTS` in `test/product-operation-catalog.test.ts` lists. Every domain route declares its operation through the product router: declaration and mounting are one statement, so a domain route cannot exist without a catalog descriptor. `productRouter` composes one policy gate (`product-operations/policy-gate.ts`) in front of every operation's handlers, so a route added later is enforced automatically.
- **One audit emit, at the choke point.** `src/product-operations/audit.ts` is mounted once at the composition root, ahead of the routes, and writes the audit row for every Product Action and every refusal of one: only a middleware wrapping the gates sees a gate denial, and the router-stamped descriptor names the operation, so new routes are audited automatically. **Never hand-place an emit in a route.**
- **Deterministic 400s are an FE contract.** Anything a route rejects deterministically (caps, shape refines) must be mirrored client-side with recoverable copy. The FE resubmits the same state, so an unmirrored deterministic 400 is an unrecoverable loop (see `apps/web/AGENTS.md`). Corollary: validate that every ACCEPTED payload is representable by its own degradation path (the fold-budget refine).
- **GitHub rides a binding.** Every user-token GitHub call rides a binding from `AuthDeps.bindReviewerGitHub` or `AuthDeps.bindOperatorGitHub`; `main.ts` injects `github`'s, `buildAuthDeps` binds them over the throttle-off test octokit, and a fake suite passes the `github/testing` fake's. Nothing under `src/` constructs an octokit or mocks `github`; hand-rolled refresh locals and attempt counters are banned.
- **The update check is anonymous.** `src/update-check` fetches the release manifest with a bare GET and the runtime's default User-Agent, nothing about the instance in the request; a `dev` or `0.0.0` `SERVER_VERSION` and the instance config's `updateCheck.enabled: false` never fetch. Composition injects `fetch`.
- **Hono's context parameter is `c`** in every handler and middleware, the framework's idiom and the one exception to the rule against one-letter locals (`docs/dev/coding-standards.md`, Types and values).

## Verification

- Tests: full-URL wire suites stay in `test/` (the byte-identity proof); unit tests colocate (`controller.test.ts`, `logic/x.test.ts`). The tell is whether the file imports `app.request`.
- `test/product-operation-catalog.test.ts` proves the composed app matches the table and pins each operation's policy.
- `test/refresh-postgres.test.ts` is the one real-Postgres suite: it reads `MERGEBRIEF_TEST_POSTGRES_URL`, skips locally when unset and fails under `CI`.
