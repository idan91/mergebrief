# Sessions, tokens and instance access (enforced, don't weaken)

- **The instance is closed unless its config names you (`access/instance-access.ts`).** An Operator or an `allowed.users` id needs no GitHub call; anyone else needs an unsuspended installation of the App on an `allowed.accounts` account or an Operator's personal account, read on the viewer's token. Paste, Regenerate, turning on generate on every push (it may release a held head) and token mint call `createInstanceAccessCheck` after their own gates: a refusal is 403 `account-not-allowed`, an unanswered read fails closed. The OAuth callback and a token rotation call `checkTokenAccess` on the bare token: a refused sign-in stores nothing, and a refused rotation retires the grant, while an unanswered read or a config naming nobody keeps it, because a retirement cannot be undone. `createInstanceAccessCheck` is async, so it is not a descriptor field. A new route that queues a paid run or mints a credential calls it.
- **A cookie principal on an unsafe method proves same-origin.** `sessionLayer`'s cookie branch refuses POST, PUT, PATCH and DELETE unless the request carries `Sec-Fetch-Site: same-origin` or an `Origin` equal to `PUBLIC_BASE_URL`'s origin; absent both it fails closed. The wire is a plain 403 `forbidden`; the ledger says `cross-origin`. Bearer is exempt because it never rides ambient. Logout sits outside the layer (an unknown cookie still answers 200) and runs the same check by hand; a new cookie route outside the layer owes the same. The pure decision is `routes/auth/session/logic/same-origin.ts`.
- **The token refreshes at most once per REQUEST**, shared across every GitHub call in the request (`SessionCredential.renewToken` under the binding the gate builds and hands on as `repoAccess`, so the gate's read, its walk and the route share one renewal). Per-call-site refresh either misses mid-request expiry or refreshes twice. A rotation GitHub refuses retires the grant on both channels (`retireGrant`: sessions deleted, tokens revoked) and answers 401; one GitHub does not answer, or that waits past the grant's 2-second lock bound, keeps every row and answers 502; one the session key cannot open or seal, or one GitHub refuses for the App's own credentials or settings, keeps every row and answers 500.
- **A grant's last live reference takes its GitHub token with it.** Every request-path delete or revoke that leaves a grant with no session and no live token (logout, sign out everywhere, an expired session, an API token revoke) revokes the access token at GitHub after commit, through `revokeOrphanedGrantsAtGitHub`; a failure warns `grant.revoke.fail` and the request answers as before. `retireGrant` on a dead token and the revoke webhook skip it: GitHub already killed the token. A rotation the instance's access rules refuse revokes after it retires.
