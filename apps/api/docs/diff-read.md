# Diff read and span thread (enforced, don't weaken)

- **The diff read serves what the worker's marks came from.** `read-diff` classifies `(base, head)` from stored rows only (`reads/logic/span-keys.ts`): a Brief's own pair, or a base equal to the PR's current base, is GitHub's compare; a pair with a `comparison_marks` row is that revision span, read with `brief-core/pr-span`'s `readPrSpan` on the bases the row stores, never bases inferred from Brief rows; an unmarked pair whose narrative or delta the worker skipped as too large answers 413 `diff-too-large` with no GitHub call; any other pair is a compare. A database error on that read fails the request, never falls back to a compare. Every answer the route itself gives, error answers included, carries `mergebrief-diff-mode` (`DIFF_MODE_HEADER`): which read served or refused. The cache key adds the row's bases, so a rewritten row reads afresh. One span read per key is shared by every waiter and stops only at its deadline, never at a caller's disconnect; the deadline, or a stopped span thread, answers 504 `diff-fetch-timeout` to every waiter.
- **A span's diff-sized steps run off the event loop.** `reads/logic/span-thread/` owns the process's one `worker_threads` thread and runs `brief-core/pr-span`'s `PrSpanRunner` steps on it (the plan off both PR diffs, each line diff, the build), so only GitHub reads and message passing stay on the event loop. It starts with no node flags and no environment, so no secret or config reaches it, and imports only `brief-core/pr-span`. A stop or crash rejects every pending step with `SpanThreadError`. It runs the worker's own functions and constants, so the API's span equals the worker's for the same refs.
