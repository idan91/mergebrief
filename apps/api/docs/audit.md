# Audit (enforced, don't weaken)

- **A read is never audited**, denied reads included. Queries fire on every render and already produce an `api.access` line.
- **Ids, tokens and numbers only**: no bodies, no free text. A route that knows the row it acted on calls `stampAuditTarget`; a route whose wire code is a deliberate collapse (the gate's uniform 404) calls `stampAuditReason` so the ledger can say `no-repo-access` while the response still says 404. Otherwise the denial reason is the wire code, stamped by `buildErrorResponse`.
- **HTTP status stays out of the row.** `outcome` plus a reason token is the vocabulary; a status would re-introduce the existence leak the collapse exists to prevent.
- `client` is matched against this project's own CLI name, never a `product/version` SHAPE (a caller could write its own address into the ledger). Forensic: **nothing may ever branch on it**, and a derived value must stay inside persistence's `AuditClientSchema` (a store-rejected value throws inside the emit and loses the row).
- **A row is keyed on the world the request acted in**, the `auditScope` the access steps stamp in turn (`stampAuditScope`): the pull request row's world when a row resolved, else the repo's, else the credential's own. An installation world records its id; an owner world records a NULL installation with `source: url` (a url row, a repo in no installation, or a route with no repo such as token mint and revoke). A refusal that resolved no credential at all is not recorded. Documented in `docs/self-host/data-and-scaling.md`.
