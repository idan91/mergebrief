# BRIEF-196 — Product Operation catalog, route registration, CI drift gates

Implementation plan. Source of truth for scope: BRIEF-196 ticket + BRIEF-122
locked decisions and 2026-08-15 round-2 settlement.

## Goal

Every authenticated domain operation enumerable, classified, and mechanically
mapped to backend routes and CLI commands. Today routes register ad hoc in
`packages/api/src/app.ts` and nothing guarantees a CLI equivalent exists — the
agent-complete-CLI premise has no enforcement.

## Scope boundaries

- Migrates the **existing** operations only: 13 Product Queries + 10
  Product Actions (7 review/GitHub actions; 3 credential/setup actions stay
  web-only, `agentAvailable: false`). The 17 Review Session actions register
  later under BRIEF-197. (The ticket's "14 queries" audit count could not be
  reproduced from the registered surface — the only unregistered GET is
  `/api/version`, which this plan itself excludes; 13 is the enforced count.)
- Not Product Operations (never registered): OAuth callbacks, logout,
  webhooks, version checks, UI-only presentation state, CLI profile storage,
  bookkeeping automatically caused by review submission.
- A public backend composite is itself a Product Action with an equivalent
  CLI command; client-only compositions are not.

## Process requirements

### git-eng (mandatory for ALL git operations)

- Branching: 3-PR stack, `feature/BRIEF-196/catalog-primitives` →
  `feature/BRIEF-196/route-migration` → `feature/BRIEF-196/manifest-ci-gate`;
  each PR based on the previous, retargeted to main as predecessors merge.
- Commits: agent commits in logical chunks. **Pre-commit gate: dispatch
  `security-reviewer` + `performance-reviewer` in parallel on staged changes
  before every commit; findings ≥80 confidence get fixed and re-run until
  clean.**
- No `Co-Authored-By` trailers; no AI-attribution in PR bodies.
- PR titles: `[BRIEF-196] feat: <Part> In Title Case`.
- Per-PR gates before push: root `pnpm lint`, package typecheck + tests,
  `fable-reviewer` pass (iterate on medium+ findings; 2-round budget).

### Mandatory specialist skills

- `typescript-eng` — strict TS, `as const` maps + `ValueOf`, named exports,
  Result-for-expected-failures.
- `tdd` — registry, wrappers, and gate scripts are built test-first.

## Parts / PRs

### PR 1 — Catalog primitives + ADR (~450–650 LOC)

**Model: Fable 5, high effort, main session** (design-heavy: the registration
seam every later ticket builds on).

1. New `packages/api/src/product-operations/` module (owner-first: backend
   owns the catalog):
   - `types.ts`: `OPERATION_KIND` (`QUERY: "query"`, `ACTION: "action"`),
     `WRITE_CLASSIFICATION` (`READ: "read"`, `PRIVATE_WRITE: "private-write"`,
     `EXTERNAL_WRITE: "external-write"`) as const maps + `ValueOf`; operation
     descriptor: stable kebab-case id, kind, classification, `agentAvailable`.
   - Registry: collects descriptors at route composition; enumeration API for
     the manifest generator; duplicate id = `throw` at startup (programmer
     error, not Result).
2. `productQueryRoute` / `productActionRoute`: thin wrappers over the existing
   Hono route-factory convention. A route file exports its factory wrapped
   with its descriptor; handlers stay colocated; `app.ts` keeps importing
   routers. Queries must declare `READ`; actions declare `PRIVATE_WRITE` or
   `EXTERNAL_WRITE`.
3. ADR 0039 — Product Operation catalog (taxonomy, registration seam,
   manifests, CI gates, `agentAvailable`).
4. Tests first: descriptor validation, registry enumeration, duplicate
   detection, wrapper passthrough (wrapped route behaves identically).

### PR 2 — Migrate existing routes (~600–900 LOC, mechanical)

**Model: Opus 5, main session, sequential after PR 1** (execution work; PR 1
fixed the pattern).

1. Wrap all existing domain routes in `packages/api/src/routes/` with the
   audited classification. Route files touched: pulls, repos, reads,
   conversation, review-submit, mark-ready, inline-comment, resolve-thread,
   generate, collaborators, installations, tokens. (auth registers only the
   excluded OAuth/logout arms and pr-view registers no routes — neither is
   wrapped.)
2. Excluded routes (webhook, version, OAuth/logout arms) stay unwrapped.
3. Per-route test updates only where the wrapper changes observable
   composition; no behavior changes.
4. The audit list (13 + 10 with ids and classifications) is committed as the
   catalog itself — reviewable in one file-by-file diff.

### PR 3 — Manifests + CLI mapping + CI gate (~400–600 LOC)

**Model: Fable 5, medium effort, main session, sequential after PR 2.**

1. Generator: compose the registry without serving (app factory already takes
   injected deps) and emit `packages/api/product-operations.manifest.json` —
   committed, regenerated by script, drift = CI failure (byte-compare, same
   pattern as the gh-axi skill drift test).
2. CLI mapping: `packages/cli/product-operations.map.json` — op id →
   `mergebrief` command. Check script verifies exhaustive mapping both
   directions.
3. Gap entries: `{ reason, owner, ticket, expiry }`; missing or expired gap =
   exit 1. Expected-failure reporting via Result; process exit codes at the
   bin boundary.
4. Wire into root `pnpm lint` (or a `pnpm check:catalog` invoked by it) and
   `ci.yml`. Deterministic — no live API, runs on every CI pass.
5. Tests first for the check script: complete mapping, missing mapping, gap
   with/without expiry, expired gap, manifest drift.

## Sequencing

Strictly sequential (each PR builds on the last), main thread throughout.
Stack merges via the usual squash-merge + `rebase --onto` realignment
(git-eng). No eval-harness runs — this ticket never touches the generation
surface.

## Acceptance

- CI fails on: unregistered domain route (manifest drift), unmapped operation,
  expired/undocumented gap.
- `app.ts` composition unchanged in shape; zero behavior change to any route.
- Catalog enumerates 23 operations with the audited classifications;
  3 credential/setup actions carry `agentAvailable: false`.
- ADR 0039 on main.
