# BRIEF-198 — CLI capability discovery and fail-closed compatibility

Implements the locked decisions from the 2026-08-21 grill (recorded on the
ticket): a server capabilities endpoint serving the ProductRouter registry, a
`mergebrief capabilities` command joining it with the CLI's committed command
map, a `--require` fail-closed check with new exit code 6, and a
manifest-fingerprint drift warning. Scope amendments already locked: no
per-operation versions, no `operations describe` subcommand.

## Locked design (do not re-litigate)

1. `GET /api/capabilities` serves the composed registry — itself a registered
   Product Query (`read`). Response: `{ operations: [...4-field descriptors],
   catalogFingerprint }`. The CLI adds what only it knows: `cliVersion`, its
   command map, and its own baked fingerprint.
2. Compatibility = two facts, both required: the server registers the
   operation AND this CLI binary maps it to a `command` (a `gap` or `webOnly`
   entry fails the check).
3. Fingerprint = sha256 of the rendered manifest bytes (`renderManifest`
   output — identical to the committed
   `packages/api/product-operations.manifest.json`). Server computes from its
   live registry; CLI carries a committed copy regenerated by the existing
   map-check script. Mismatch while all required ops pass = one stderr
   warning line, never a gate, never a nonzero exit.
4. `mergebrief capabilities [--json] [--require <id>...]` — one command, no
   subcommands. Any required op failing → exit **6 = INCOMPATIBLE**
   (additive to the 0029 table), empty stdout, stderr names every missing op
   and which fact failed. All requirements met → normal output, exit 0.
5. ADR 0029 amendment rides PR 1: capabilities sanctioned as the third
   CLI-synthesized shape; handshake framed as fail-closed compatibility
   check, not negotiation; exit 6 added; stream/exit invariant untouched.
6. BRIEF-199 owns where a skill's requirements list lives; this ticket only
   fixes what the check consumes (operation ids via `--require`).

## PR 1 — api: capabilities endpoint + fingerprint (~300 LOC)

Branch: `feature/BRIEF-198/api-capabilities`. Base: `main`.

1. **Fingerprint helper** in `packages/api/src/product-operations/manifest.ts`
   (or sibling): `computeCatalogFingerprint(operations): string` = sha256 hex
   of `renderManifest(operations)` (node:crypto). Tests: stable across
   registration order (registry already sorts), changes when any descriptor
   field changes.
2. **Vocabulary + route**: add `READ_CAPABILITIES: "read-capabilities"` to
   `PRODUCT_QUERY_ID` (`ids.ts`). New
   `packages/api/src/routes/capabilities.ts` on the ProductRouter `.query()`
   seam (pattern: `routes/version.ts` for gating, `routes/pulls.ts` for
   `.query()`), mounted in `routes/index.ts`. Handler serves
   `{ operations, catalogFingerprint }` from the composed registry —
   descriptors verbatim in registry order, `no-store`.
   Note the self-reference is virtuous: the endpoint appears in its own
   output, the manifest gains one entry, and the derived route-table backstop
   test must keep passing.
3. **Regenerate manifest** (`pnpm -C packages/api manifest`) — one new
   `read-capabilities` row. Map-check will now fail exhaustiveness for the
   new id; add the CLI map entry in the same PR (see step 5) or a dated gap
   consumed by PR 2 — prefer the real entry: `"read-capabilities":
   { "command": "mergebrief capabilities" }` (map references commands, the
   binary ships in PR 2; the check script validates ids, not binaries —
   confirm; if it round-trips against the commander tree via
   `command-paths.ts`, use a dated gap expiring with PR 2 instead).
4. **ADR 0029 amendment** (same PR): amended section listing `capabilities`
   as the third sanctioned CLI-synthesized shape (`delta`, `auth status`,
   `capabilities`), exit 6 appended to the table, "skew visibility" clause
   extended: discovery is a fail-closed compatibility check, never
   negotiation. `docs/api-changelog.md` entry for the new endpoint.
5. Tests: route gating (401 without session), shape, fingerprint matches the
   committed manifest hash byte-for-byte (reads the committed file — this IS
   the drift tripwire in test form).

## PR 2 — cli: capabilities command, --require, exit 6 (~400 LOC)

Branch: `feature/BRIEF-198/cli-capabilities`, stacked on PR 1's branch.
Retarget to `main` after PR 1 squash-merges (git-eng stack realign:
`rebase --onto`, patch-id proof).

1. **Exit code**: `INCOMPATIBLE: 6` in `packages/cli/src/exit.ts` (doc
   comment: additive-only table).
2. **Baked fingerprint**: extend `scripts/check-operations-map.ts` (+
   `operations-map-lib.ts`) to write/verify a committed
   `packages/cli/src/generated-catalog-fingerprint.ts` (or `.json` beside the
   map) holding the sha256 of the manifest the map was checked against.
   Drift = existing `map:check` failure mode, same `pnpm lint` ride.
3. **Command** `capabilities` in `packages/cli/src/commands/read.ts` (or a
   co-located `capabilities.ts` if read.ts crowds — follow co-located
   decomposition): fetch `/api/capabilities`, tolerant-read slice
   (`operations[].id` + `catalogFingerprint`; unknown fields pass through),
   join per id with the imported map: each op gains
   `cli: { command } | { gap } | { webOnly } | { unknownToCli: true }`
   (server newer than CLI). Output shape (CLI-synthesized, additive-only):
   `{ cliVersion, serverCatalogFingerprint, cliCatalogFingerprint,
   fingerprintMatch, operations: [...] }`.
4. **`--require <id...>`**: repeatable/variadic. For each required id, fail
   fact (a) if absent from server response, fact (b) if the CLI map entry is
   not `command`. Any failure → `CliError(INCOMPATIBLE, ...)` listing every
   failing id with its reason (stream/exit invariant: empty stdout, one
   stderr line). All pass → normal stdout, exit 0.
5. **Fingerprint warning**: on mismatch (and not already failing), one
   stderr warning line; stdout stays pure JSON under `--json`. TTY rendering:
   human table (non-contractual).
6. **Docs**: `agents-guide.ts` gains the discovery/preflight section (check
   before driving a skill; exit 6 semantics; example `--require` loop).
   `map:check` embed/help updates as needed (`embed-help.ts`).
7. Tests (tdd): join logic per arm (command/gap/webOnly/unknownToCli),
   require pass/fail matrices, exit 6 + invariant, fingerprint warning
   emitted once, tolerant-read on extra server fields, baked-fingerprint
   drift check.
