## Upgrade

Do these in order. The first one has to happen before the new release starts.

1. **Replace `drafts.generate` in `mergebrief.config.yaml`.** MergeBrief now refuses to boot while the key is set, whatever its value. If you set `drafts.generate: false` to hold drafts, delete it and set `readyForReview: on` under `triggerConditions:` instead; otherwise just delete it ([repo-config.md](https://github.com/idan91/mergebrief/blob/v0.3.0/docs/self-host/repo-config.md#related-instance-block-drafts-operator-side)).
2. **Give the GitHub App two new read permissions.** In the App's settings, set **Checks** and **Commit statuses** to **Read-only** and subscribe to the **Check run** and **Status** events. Then accept the updated permissions on each installation's settings page on GitHub: changing the App does not reach an installation until it accepts. Until then, that installation's `bots` conditions on App bots (Unblocked, CodeRabbit, Claude, Greptile) and `ci` conditions with a check to read hold pushes as missing the permission ([github-app.md](https://github.com/idan91/mergebrief/blob/v0.3.0/docs/self-host/github-app.md#upgrading-an-app-you-already-registered)).
3. **Update API clients for two breaking changes.** The `409` code on `POST /api/repos/:repoId/pulls/:prNumber/regenerate` is now `generation-running`, no longer `generation-held`, and `draftPolicy.generate` is gone from `GET /api/repos/:repoId/pulls/:prNumber`. Install `mergebrief@0.3.0` with the server, and change any script that matches either name ([API changelog](https://github.com/idan91/mergebrief/blob/v0.3.0/docs/api-changelog.md)).
4. **Run the chain.** Four migrations run on start, as usual: they add the held status, the columns that hold trigger-condition state and the every-push switch, and an index, and need nothing from you.

## Trigger conditions

- **Choose which pushes get a brief.** A repository's `.mergebrief/settings.yaml`, or the instance config for every repository, can require a push to be ready for review, within a size, labeled, titled with a keyword, aimed at a base branch, touching certain paths (a repository's settings.yaml only), requested for review, passing CI, or reviewed by a bot such as CodeRabbit or Claude. An `any:` group passes when one of its members does ([repo-config.md](https://github.com/idan91/mergebrief/blob/v0.3.0/docs/self-host/repo-config.md#triggerconditions-what-a-push-must-meet-before-it-generates)).
- **A push that misses one waits as held, and spends nothing.** The pull request page, the CLI and the Entry comment list what it still needs, and the Inbox row shows its first reason. It generates by itself once everything passes, and a new CI result or bot report checks it again. Anyone with push access can press Generate to brief it now.
- **Generate on every push.** On a held pull request's page, the menu beside Generate brief generates the held push now and skips the conditions for every later push, until you turn it off from the inbox row's menu.
