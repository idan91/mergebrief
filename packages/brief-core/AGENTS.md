# packages/brief-core: agent notes

The Brief domain core. Everything production consumes to generate a Brief: the output schema + closed label vocabulary, the taxonomy prompt, the categorize engine (behind the `generators` port), repo-context (`.mergebrief/` semantics), delta/revision/comparison logic, the anchored-generation plan and stitch, and the huge-span guard.

Repo-wide conventions apply (root AGENTS.md); refinements below.

## Map

Curated subpaths exist beside the entry: `brief-core/types` (`src/types.ts`) serves apps/web, the worker, the eval harness, `persistence` and `repo-config`, `brief-core/gh-exec` (`src/github/exec.ts`) serves the `gh` fetchers in `tools/categorizer`, `brief-core/remap` (`src/diff/remap.ts`) serves `persistence`'s carry-over, `brief-core/path-matching` (`src/path-matching.ts`) serves apps/web and the worker's `paths` condition (`matchesAnyGlob`, a budgeted scan of many globs over many paths), `brief-core/hidden-chars` (`src/hidden-chars.ts`) holds the hidden-character set the prompt escapes, `formatDisplayPath`, which apps/web and the CLI render every GitHub-sourced path through, and `formatDisplayText` for titles and prose, which keeps the marks and joiners text needs, and imports nothing (`hidden-chars-imports-nothing`), and `brief-core/chunk-layout` (`src/diff/chunk-layout/`) holds the diff parser, the chunk slicer, the expansion gap finder, the file status read off the hunk header and the per-chunk counts that both apps/web and the worker run, plus the header path reader the CLI's `--group` filter runs; it runs in the browser, so it imports nothing at runtime beyond `types` (`chunk-layout-imports-only-types`). `brief-core/artifact` (`src/artifact/`) holds the stored-body schemas, the write checks and the tolerant readers for a Brief, a Delta Brief and a Revision narrative. Every reader returns a `Result` and fails on a broken core, whatever the body. The Brief reader reads the current shape only: a group without an id fails it. It also drops an invalid optional section, nulls an effort it does not know, drops a malformed risk token, moves a chunk naming no group into the unattributed remainder and keeps groups sharing an id (only the write check refuses those), reporting each in `issues`. The narrative reader strips unknown keys and drops or nulls the same optional fields, also reporting each; the Delta Brief reader tolerates nothing. A delta row holds a Delta Brief, the span's `deltaSkipped` record (`shapeDeltaSkipped`) or its `deltaUnchanged` record, told apart by `artifactKind`; `checkDeltaForWrite` accepts all three. A narrative row likewise holds a narrative, `revisionNarrativeSkipped` or `revisionNarrativeUnchanged`. `readBriefSessionFacts` is the lean read `persistence` takes off a stored Brief body for its Review Session store and the Brief's stored record counts: chunk ids, group ids, flags with their chunk region, file paths, and the markable Chunk count (Chunks plus unattributed files). `brief-core/shortened` (`src/generation/shortened/index.ts`) is no leaf: it serves the worker's lockfile child process, which loads the lockfile parsers without the generation graph's provider SDKs. Three more leaves serve members that must not load the generation graph: `brief-core/pr-stack` (`src/pr-stack/`) for the api, the worker and `github`, `brief-core/pr-url` (`src/github/pr-url.ts`: `parsePrUrl`, `PrLocator`) for the api, and `brief-core/media-address` (`src/media-address/`) for apps/web and the api: it reads the three raw addresses of a committed file, refuses an escaping path, and writes the one normalised address; it imports nothing at runtime beyond `types` (`media-address-imports-only-types`). `brief-core/sanitized-markdown` (`src/sanitized-markdown/`) is the one Markdown pipeline people's text goes through, GFM parse, raw HTML, then `rehype-sanitize` under the one render schema; apps/web's renderer runs its plugin lists, and it loads no workspace runtime (`sanitized-markdown-imports-no-workspace-runtime`). `brief-core/media` (`src/media/`) reads the Media items of a description off that sanitized tree for apps/web and the worker (`media-imports-only-its-pipeline`).

`brief-core/pr-span` (`src/diff/pr-span/`) reads the revision span between two heads as the diff of the PR's own diffs, for the worker and the api: `readPrSpan` over a `PrSpanSource` port (a fast-forward whose two PR diffs share one merge base is the between-heads compare as served, unfiltered; otherwise both heads' PR diffs from the compare endpoint, the swapped paths of a base-rename candidate, which pairs only when both read absent, equal base SHAs included since each PR diff starts at its own merge base, then both blobs of each content-changed file and of each file whose runs match over a moved base but whose context differs, which reads unchanged only when its filtered line diff is empty), `buildPrSpan` as its pure core. It returns the filtered and unfiltered between-heads diff and the hop, `too-large` past `MAX_SPAN_CHANGED_FILES` before any blob read; it loads no generation graph. The filtered diff keeps each run touching either head's PR change (a run that can slide over equal lines touches when any place in its range does) with its context cut at every dropped run. Its text is a function of the refs, the blobs and the constants: files line-diff in path order under `SPAN_LINE_DIFF_MAX_LINES` and `SPAN_LINE_DIFF_MAX_CHARS` (UTF-16 units, `WIDE_TEXT_CHAR_WEIGHT` each for a file with a unit above U+00FF on either side, charged before any pass reads the text), and the file neither can afford and every later one take the fallback. Each file's `maxEditLength` is what its `LINE_DIFF_MAX_WORK_SHARE` of the work `SPAN_LINE_DIFF_MAX_WORK` has left buys at its compare cost (weighted characters plus `LINE_DIFF_CHARS_PER_LINE` per line, per edit step); a file whose line counts already need more edits falls back alone with nothing charged, and one whose diff passes it falls back alone, charged its share. jsdiff's timeout (`LINE_DIFF_TIMEOUT_MS`) is a crash-only stop far past what the work bound lets one diff cost, so machine speed never picks the text; it also takes the fallback, never a transient failure. Every step whose cost grows with the PR diffs or the blobs (the plan off both PR diffs, each file's line diff after the bounds set its edit length, the build, the fast-forward build) runs through an optional `PrSpanRunner` (default in-process; the api's runs them on a thread), each step a function of its input alone, so every runner yields the same span; only strings and slim results cross it, and a step that rejects with a `SpanRunnerError` reads `transient`, and any other throw propagates.

The entry loads the whole generation graph and every provider SDK: only `apps/worker` and `tools/*` import `"brief-core"` by value, every other member imports a leaf subpath, and a new leaf joins `LEAF_SUBPATH_FILES` in `.dependency-cruiser.cjs`.

What the layout can't show:

- `types.ts` takes the origin vocabulary from `generators/generation`, never the `generators` entry, so the Brief shape loads without an adapter. It re-exports none of it: `Effort`, `Generation`, `Anchor` and kin come from `generators/generation`, `AnchorStates` from `types/generations`, `TicketTrackers` from `types/trackers`.
- `types.ts` (Brief schema + closed vocabulary, mirroring `docs/vocabulary/labeling-schema.md` and `risk-surface.md`) and `generation/prompt/` are generation surface (root AGENTS.md's eval gate).
- `diff/` and `anchoring/` are mechanical parsing and partition, no model calls.
- `anchoring/` plans the carry off the revision span (`planAnchoredGeneration`): a group freezes when the span left each file it owns alone as it was and every range moves through the hops; groups sharing a file carry together, and a frozen group sharing a file with a re-looking one re-looks too, repeated until none does (`settleSharedFiles`); no span re-looks every group. The stitch refuses a model claim on a frozen group whose files another frozen group still carries (`refuseSharedClaims`), so the carry stays and the claim's drift goes. The plan names its `AnchorWarnings` (`span-unavailable`, `hunks-unpaired`) from structured refusal causes, and the stitched Brief stores them as `anchorWarnings`, outside the model-facing schema. The stitch keeps the order whole: a slip's step follows its frozen id's step, and a group named twice keeps its first.
- Two whole-diff splitters exist on purpose. `diff/file-diff`'s `splitDiffByFile` feeds the prompt and the generation-side reads. `chunk-layout`'s `splitUnifiedDiffByFile` is what the page reads rows through, so a reader whose rows must match the page (the worker's counts, any web view) uses it.
- `generation/brief/` holds `generateBrief`, the one Brief generation entry the worker, the eval harness and the dev CLI call: plan, anchored generate and stitch when a previous brief is passed, then `generation/final-validation`'s one pass over the final chunk set, typed warnings returned. Every brief it returns carries `inputFingerprint` (`generation/input-fingerprint.ts`: the rendered title, branch facts, description, linked context and primary ticket, and the repo context as loaded). A span that changed no file, left every group carrying and meets a previous brief whose fingerprint equals this run's makes no model call, whatever the call plan: the fingerprint is checked before `onPlan`, then `onPlan` writes the hop and the previous brief's prose and intent are stitched over the new head under its own generation stamp (`carryDraftBrief`). Any other run, a previous brief with no fingerprint included, takes the model path below. A multi-call plan runs through `runMultiCall`: over a previous brief it plans and fires `onPlan` like the single call, the grouping and detail calls cover only the files outside frozen groups (frozen groups ride the grouping call as a code-free index; a group it lists under a frozen id is a numbering slip and descends under a temporary id, and a file run steps over the frozen files' ids), then the same stitch carries frozen groups and descends re-looked ids, one `validateFinalBrief`, `ranAs: multi`. Nothing after the model call fails it: the stitch only merges, and a chunk naming no final group drops into the unattributed remainder. Whether to anchor and the anchor stamp stay with the caller.
- `generation/size/` decides the call plan (`decideCallPlan`: 400k input tokens or 120 hunks, or the generator config's `forceMultiCall`), and `generation/brief/` routes on it only for a caller that passes `multiCallHooks` (the worker's, or `{}` from the eval harness and the dev CLI); without them every brief runs as one call. A multi-call run lives in `generation/multi-call/`: `grouping.ts` renders the grouping call over the outline `generation/outline/` chose (the full diff, then `lines-40` down to `files`, every form redacted per file by `generation/redacted-diff.ts` before any line is dropped), `hunk-map.ts` resolves the grouping call's hunk map into owners, `batches.ts` packs whole groups into detail batches of at most 80 hunks and half the single call's input budget in diff tokens, and halves a cut one of two or more hunks, `detail.ts` weighs each hunk once (a hunk over that budget alone is cut to its head lines, the rest left unattributed) and renders the detail calls (rules in system; the PR text, the repo attributes and the grouping output ride the user message's cached first block, `userPrefix`), and `index.ts` orchestrates: call 1 alone, then `detailConcurrency` at once, code merges. The worker hooks in (`MultiCallHooks`): `onGroupingDone` names the detail calls no stored part answers (by the same parse the reuse runs) and may throw, `onDetailStart` fires once before the first detail call, if any, `loadPart` / `onPartDone` resume a run from stored parts keyed `grouping`, `detail:<n>`, `detail:<n>:<half>`. A cut detail call of two or more hunks splits once and a cut one-hunk call fails the run; a cut single call re-runs once as a multi-call run, and a retry whose span holds that run's grouping part resumes it before any single call. Every grouping or detail prompt text is generation surface like `prompt/`.
- `generation/shortened/` reads a lockfile's package changes from its text at base and head and `.gitattributes` once per run (`readLinguistAttributesByPath`, a run-wide match budget whose unresolved path count the engine logs). That `.gitattributes` is the one at the repository root on the default branch; a nested one is not read. A shortened file's chunk is code-written (`buildShortenedChunk`), and `adds-secret` still reads the full patch. `generation/redaction/` knows fixed credential formats plus one rule by name (`keyed-secret`: a literal under a secret-named key, 8 to 256 characters holding a letter and a digit; a name-shaped one such as a design token is `keyed-name`, hidden but never `adds-secret`, unless the key holds a password); a format that covers the whole value keeps its own marker, and every new pattern takes a row in the `pattern cost` or `hunk header cost` test.
- `github/` keeps the PR shapes (`types.ts`), the url parser and the `gh` exec plumbing the GitHub tracker's transport uses; the dev CLI's `gh` fetchers live in `tools/categorizer`, and the worker uses its own github-port.
- The primary ticket is harness data end to end: `context/primary.ts` maps the fan-out outcome to `intentCheck.primaryTicket` after validation; the model sees the ticket only inside `<primary_ticket>` and never the stamp.
- `context/trackers/` holds one folder per ticket tracker with the same four entries: `references.ts` (syntax and URL form), `transport/` (`port.ts` plus one file per implementation, listed in an `XTransports` map), `read.ts` (`createXRead(shared, transport)`), a `read/` folder once the read grows support files, and `index.ts` (the `Tracker`). A new tracker is that folder, a line on `TrackerTransports`, a line in `TRACKER_BY_KIND`, and a slot at each root. `resolveTrackerReads(settings.tracker, root)` builds one read per bound slot; an unbound tracker is never a read, and a bound slot that cannot build refuses only when it is the repo's tracker. GitHub's installation transport reads another repository's issue only when its API answers that the repository is at least as widely visible as `pullRequestRepo` (`isVisibleToReadersOf`: visibility, not membership), refusing when that answer fails; a Notion page URL reads only when the page sits in a board the repo lists. Providers return `Result`, the fan-out fails open per provider, the SSRF guard lives in `providers/url/guard.ts`, a fetched HTML page loses its comments, `head`, scripts, styles, templates and `noscript` before the snippet cap (`providers/url/page-text.ts`, read up to `MAX_PAGE_CHARS`), and every fence tag the prompt uses is listed once in `generation/fences.ts`. In every prompt, every untrusted field (title, description, branch facts, file paths, links, tickets, comments, the narrative's brief context) goes through `sanitizeUntrustedText` and every diff through `sanitizeUntrustedDiff` (`generation/untrusted-text.ts`); a field the prompt shows on one line (an id, a title, a path) takes `sanitizeUntrustedLine`, which also turns each line break into a space; a brief summary shown beside other sections of one fence takes `sanitizeUntrustedSummary`, which escapes every heading line but `## Changelog`; a path inside diff-derived text, such as an outline's file title, takes `sanitizeUntrustedDiffLine` so it reads as the diff header spells it, on one line: what GitHub hides comes out of prose, hidden characters become visible escapes in a diff, and every tag of the union, in any spelling, becomes `REMOVED_TAG_MARK` so the text around it cannot rejoin into a tag. The quote corpus is the same sanitized text, and the quote check drops the mark on both sides. A chunk path the model copied in its sanitized spelling maps back to the raw path (`restoreRawPaths`) before validation. A summary heading an anchored call copied in its escaped spelling maps back to the heading (`restoreEscapedHeadings`). The title, description, branch facts and diff ride in `<pr_title>`, `<pr_description>`, `<pr_branch_facts>` and `<pr_diff>`, and every user message ends on a reminder that tagged text is data. When the description holds Media, the single and grouping calls add only a note keeping Media out of `summary`, and `generateBrief` then makes one Summary Media call (`generation/summary-media/`: the title, the description, a numbered `<pr_media>` block with kind, caption and heading per item, sanitized, never an address, and the brief's summary in `<brief_summary>`). The brief and grouping schemas compile just under the Anthropic API's grammar cap, so no Summary Media field rides them; any other request stays byte-identical. Only the `anthropic` adapter compiles that grammar, so evals and CI cannot see the cap: a change to a generation schema runs `pnpm -C tools/categorizer smoke:schemas` before merge, which takes a real API key, so a human runs it. A media call that fails on its answer or provider ships the brief without Summary Media and a `summary-media-failed` warning; an abort or run signal still propagates. The model answers item numbers; the generator maps them to `MediaKey`s and trims (caps, repeats, unknown numbers and positions, a pointer with no items or label), warning with counts only. The Product diff is written the same way and for the same reason: after a brief that ran as one call, `generateBrief` makes one Product diff call (`generation/product-diff/`: the title, branch facts and description, the finished brief's change-groups by id, title and summary in `<pr_change_groups>`, and the whole diff in `<pr_diff>`), fans the answer out to the stored shape and trims it (`validateProductDiff`: unknown group ids, a change left with none, a repeated row, a before at odds with its source) so what it stores always passes the write check. The call lists every change it finds, up to 16; the cut to the first eight that pass and `hasMore` are the pipeline's, and the call's own `hasMore` counts only from an answer of 16. A multi-call run makes no such call and stores the section as `unavailable`; a failed call, or an answer with no row left, ships the brief without the section and a `product-diff-failed` warning. A no-call carry keeps the previous brief's section as it is. An anchored one-call run shows the call the previous revision's rows in `<pr_previous_product_diff>`, without their group ids, and a system section asking it to keep the wording of a row that still holds; a previous revision with no rows leaves the request a fresh one. A link, image or reference definition in a Markdown field (Brief and Delta Brief summary, Delta Brief `commentsAddressed`) is dropped (`generation/unseen-links.ts`), a link's label kept, with a count-only warning, unless its destination is an absolute `http(s)` or `mailto` URL the prompt shows whole outside the blocks an earlier call wrote (`removeModelAuthoredBlocks`: the Anchor, the grouping, the brief summary, the change-groups, the previous Product diff, the narrative's `<brief_context>`); a new fence that carries model-written text joins that list. An intent-check issue names the bucket and the defect, never the item's wording, a group id or a URL, and a repeated one is counted.
- `contextSources:` entries reach each tracker's `createRead` through `SharedRootDeps.contextSources` (tokens by env-var name from the shared env); the block's schema is `generators`' because it rides the instance config. A root also hands the block to `buildContextQuery`, which reads the Jira site out of it once (`findJiraSite`: the site host and its link hosts) for the reference parser and the link chaser; a root never derives the hosts itself. `trackers/notion/transport/http.ts` talks to the Notion API through an injectable `fetch`; the roots that offer it a token are the worker's `main.ts` and the two dev CLIs in `tools/categorizer`; nothing in this package reads `process.env`.

## Invariants

- The Brief never approves, rejects, or scores; enums mirror the closed vocabulary docs and change only with them (lockstep tests).
- `REPO_INSTRUCTION_CLASSES` is the operative source of truth for what repo instructions may influence; class changes are argued in the PR and gate on an eval run.
