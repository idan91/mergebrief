# code-review — repo-wide agent rules

This file is the canonical repo-standards file; the root `CLAUDE.md` is a symlink to it. Rules here apply to the whole workspace. A rule lives at the level that owns it: package files refine, never restate. Every package, app, and tool carries its own `AGENTS.md` for its conventions and invariants, plus a pointer `CLAUDE.md`; a new one adds both.

- **Extensionless relative imports everywhere** (`from "./tenant"`, never `from "./tenant.js"`). Every package is bundler-resolved end to end (`moduleResolution: "bundler"`; vitest/tsx/vite). Extensions only where genuinely required (non-TS assets).
- No `enum`: `as const` maps + `ValueOf<T>`; keys SHOUT_CASE, string values kebab-case.
- Strict TS: no `any`, no bare `as` — Zod or type guards at boundaries; tests are exempt from the bare-`as` ban.
- Expected failures return `Result`; `throw` is for programmer/infra errors. Error messages never carry secrets, tokens, or connection strings.
- Named exports only (default exports where a framework requires them).
- **Function names start with a verb and name what comes back.** `getSocketAddress`, `deriveAttentionItems`, `shapeSubmitComment`, `collectChunks`. Not `socketAddress`, not `commentOf`, not `withoutDiffRows` — a bare noun, an `xOf` suffix and a preposition all say "of what" instead of what you get. A function returning either a value or a refusal is `resolve*`, matching `resolveWrite`. Route factories keep the established `xxxRoute` / `xxxRoutes` shape.
- **Zod schemas live beside their owner** — the route, operation, store, or script that parses with them. The ban is on schemas serving more than one owner (a cross-owner `schemas.ts` grab-bag); a domain folder's own `schemas.ts` is fine. Duplicated wire bounds share one module at the closest common owner (`packages/api`'s `routes/repos/pr/wire-bounds.ts`). Named exception: `packages/brief-core/src/types.ts` IS the domain contract and keeps its schemas. `packages/types` stays types-only, zero runtime — no schema may move there.
- **Package entry = `src/index.ts`** — a curated barrel, the package's `exports["."]` target. A package root conforms when every file is the entry, `types.ts`, or a small domain-cued support file (loose count ≤ ~5). A category earns a folder only when it clarifies; generic names are defects. `index.tsx` feature barrels remain an apps/web convention.
- **User-facing copy lives in the `packages/i18n` catalog** — never hard-coded in components or route handlers. A new wire error code follows the recipe in `packages/api/AGENTS.md`; its `errors.<code>` template rides the same change.
- **Logging goes through the `packages/logging` boundary** — no bare `console.*` in `packages/api`, `packages/worker`, or server-side `apps/web` code. Secrets ride as structured fields (redacted by path), never interpolated into `msg`.
- **Every log line earns its level**: `error` = operator-actionable now; `warn` = degraded/suspicious, alertable on sustained rate; `info` = terse operational signal; otherwise `debug` or delete the line. First-class `evt` names come ONLY from the taxonomy table in `docs/self-host/observability.md` — everything else stays plain leveled logging.
- **Coverage floors ride inside `pnpm test`**: every package's vitest config commits a lines threshold; 75% is the standard. A package still under it carries a temporary floor plus a catch-up ticket. Never lower a floor to absorb a drop. A `v8 ignore` comment needs a stated reason, and is reviewed like a lint-disable.
- **CI selects changed packages PLUS their dependents** (`--filter "...[<base>]"` off the real workspace graph). Two holes need a local run before pushing: a consumer mirroring a contract without declaring the dependency (`apps/web`'s hand-rolled wire types), and any agreement that is not a package edge (a wire shape a separate service parses).
- **Comments stay lean and reference-free**: a comment earns its place only by stating a constraint the code can't show — one short line, not a paragraph. Delete rationale essays and provenance blocks. Never cite a ticket id, ADR number, PR number, or review-round name in a comment or in reader-facing docs (`README.md`, `CONTEXT.md`, `PRODUCT.md`, any `AGENTS.md`). Those references belong in the commit message and PR description. `docs/adr/**` and `docs/plans/**` are exempt.
- **Generation-surface changes run the eval harness.** The surface: `packages/brief-core/src/generation/prompt.ts`, the output schema, validators/salvage, repo-config injection, and output-affecting adapter defaults. Run `pnpm -C tools/categorizer eval` **scoped by default** — one `--case <id>` run per case whose properties could plausibly move, with the selection justified and the report included in the PR body. Full suite for prompt-wide or model-bump changes. Convention gate, never CI — live API spend. Mechanics in `tools/categorizer/eval/README.md`.
- **No nested ternaries** — one condition per ternary, no exceptions. Reach for a lookup map (`Record<State, Value>`), if/else, or an early return instead. `no-nested-ternary` sits at `warn` (67 pre-existing violations) until the ratchet to `error` lands; the rule is absolute regardless.
- **Conditional fields are assigned, not spread.** Declare the object with its unconditional fields, then assign the optional ones under an `if`; never `...(cond ? { x } : {})`. Works with `exactOptionalPropertyTypes`. Not machine-checked — reviewers hold this one.
- **`as const` map names are PascalCase and plural, their `ValueOf` type singular** — `const PullRequestSources = {...} as const;` `type PullRequestSource = ValueOf<typeof PullRequestSources>`. SHOUT_CASE is for the map's KEYS, never its name.
- **Config enters via injection at the composition root** — nothing else reads `process.env`. A package that consumes config names its composition root in its own `AGENTS.md`.
- **Names use the domain's own nouns** — no invented shorthand. Generic type parameters get descriptive names, not bare `T`, when more than one is in play.
- **Blank lines separate a function's logical steps** (parse / guard / act / respond) — no solid-wall bodies.
- **No expression nests more than two calls** — a compound boolean or computed return value gets a named const first.
- **Import the owner** — never re-declare an existing exported type, schema, regex, or fixture inline; shared test fixtures live in test utils.
- **`prop?: T | undefined` is deliberate** (`exactOptionalPropertyTypes`), not a mistake to clean up.
- **Judge a gate by its exit code, never by grepping output** (`pnpm lint` short-circuits on `&&`; prettier reports violations as `[warn]`, not "error"). Run `cmd >/dev/null 2>&1; echo $?`. In stacked work lint each branch bottom-up — a rule can pass at the tip and fail mid-stack.
- **Never search with a glob that can match a real env file** — target `.env.example` and source files explicitly (a filename-list grep still reads contents, and real env files hold live keys).
- **Review by re-deriving, not by agreeing.** Form your own read of a diff before reading the author's, then name the disagreements as reasoning gaps. A finding you believe is wrong gets a reply explaining why, not a compliance fix; a question is not a change request.
- **The artifact noun is lowercase "brief"** mid-sentence in user-facing copy; the product is "MergeBrief". Identifiers, docs and ADRs are unaffected.
- **A hands-off run never answers its own confirmation questions.** Where a skill or a plan asks the owner something — commit strategy, which specialist skills apply, a seam between phases — stop there and leave the question pending. Overnight or unattended framing widens the batch of work an agent may do; it never widens the set of decisions it may make alone.
