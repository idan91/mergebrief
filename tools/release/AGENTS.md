# tools/release: agent notes

The release tool behind `release.yml`: reads the per-release notes files, refuses a tag without one, cuts the next tag from the published ones, stamps the tag's version into the shipped manifests, writes the Release body and `version.json` the workflow uploads, and exports the public snapshot tree of a commit on `main`. `pnpm check:releases` is its gate inside `pnpm lint`; the other commands run on the workflow's checkout only.

Repo-wide conventions apply (root AGENTS.md); refinements below.

## Invariants (enforced, don't weaken)

- **One notes file per release**, `docs/releases/<X.Y.Z>.md` or `<X.Y.Z-rc.N>.md`, version in the filename only. Front matter is exactly three `key: value` lines between `---` fences: `date` (ISO `YYYY-MM-DD`, the tag day), `breaking`, `security` (`true` or `false`). No quotes, no nesting, no indentation, no repeated or other key; the parser is the schema beside it, not a yaml library. A `breaking` file carries an `## Upgrade` heading. Any other file in the directory is a refusal.
- **Every argument is known.** An unknown flag, a `--flag=value` form, a flag without its value or a stray positional is a usage error (exit 2), never a silent fallback to the no-tag path.
- **A tag needs its file.** `check --tag vX.Y.Z` refuses when the file is missing or any file is malformed, so the gate on the PR is the same gate the tag runs. `--json` prints `{ version, channel, isHighestStable, isHighest }` for the workflow; `isHighestStable` decides `--latest` on the Release, `latest` on npm and ghcr and whether `version.json` is written, never GitHub's own ordering; `isHighest` (over every channel) decides whether an rc takes the npm `next` dist-tag, so an older candidate published later never moves `next` back. The workflow passes the tags already published as `--known-tags v0.1.0,v0.2.0`, so a hotfix tagged from an older branch is placed against what shipped, not only against the notes files its checkout carries. A notes file is merged right before its tag, never ahead of another release.
- **The stamp edits a clean checkout once; the prune shapes the tarball after the build.** `stamp <version>` refuses a manifest whose version is not the `0.0.0` sentinel, writes the version and keeps every other key, swaps every `image: ghcr.io/idan91/mergebrief:dev` line in both compose files (and refuses a file with none), and touches nothing else. `prune-manifest` refuses a manifest still on the sentinel and drops `private` and `dependencies` (the bundle inlines them; the repo keeps them listed so `pnpm audit --prod` still sees them, and a published `workspace:` range would resolve to a public package of the same name). The prune runs after the last pnpm script in `apps/cli`: pnpm reinstalls before a script whose manifest no longer matches the lockfile, which prunes the bundle's inputs and fails the build. Compose files are edited line by line so comments survive; the manifest is re-serialised with two-space indent, which is what prettier writes. Nothing here commits.
- **`version.json` and the Release body come from the notes files, never by hand.** `version-json <tag> --known-tags ... --out <file>` writes `{ latest, releaseNotesUrl, releases[] }` over the stable files, newest first, and refuses unless the tag is the highest stable release among the files and the published tags, so the file is only ever written for the release that `releases/latest/download` will serve; candidates are left out, and an rc or an older hotfix gets no version.json. `release-body <tag> --out <file>` writes the Release body: for a stable tag the upgrade chain from `docs/self-host/operations.md` with the tag filled in (a test holds the two in step), a lead line for a breaking or security release, the backup and upgrade-step links, then the notes body verbatim; for an rc a not-for-production note with the `next` dist-tag, no chain. Every link is the Release page or the tag-pinned doc.
- **`cut` computes the version, never the maintainer.** `cut <major|minor|patch> [--rc] [--at <ref>] [--push] [--dry-run]`, reached as `pnpm release <level>` from the root, bumps the highest stable tag the remote holds (`git ls-remote`, never local tags; `0.0.0` when none) and numbers a candidate after the remote's candidates of that version. It fetches the remote `main` to a ref of its own first (never `FETCH_HEAD`, which any other fetch rewrites), and tags its tip (`--at <ref>` picks another commit, which must be on it; a stale clone's HEAD is never tagged by accident), refusing before any tag is written when the notes file for the computed version is missing from that commit or malformed, or when a local tag of that name exists. The tag is written locally first; `--push` is the only other network write, and a failed push reports the local tag and the retry. A hotfix on an older line is tagged by hand. Git enters through `GitPort` (`src/logic/git-port.ts`), the one file that spawns `git`, so the plan is tested against a fake and the port against a temp repository.
- **The export reads git, never the checkout.** `export --version X.Y.Z --source <ref> --dry-run [--out <dir>]`, reached as `pnpm release:export` from the root, fetches the remote `main` first and refuses a source it does not hold, lists the commit's tracked paths and writes the shipped ones with `git archive` into an absent or empty `--out` (a fresh temp dir when absent), so an untracked or uncommitted file can never ship. A relative `--out` resolves against the shell the root script ran in. Without `--dry-run` it refuses: publishing is not built yet.
- **One manifest says what is private.** `src/logic/export/paths.ts`: `include` names every top-level entry (a dir with its `/`), `exclude` holds path prefixes, no globs, applied unconditionally; a prefix with nothing tracked under it passes. A top-level entry in neither list refuses the export (`unclassified top-level path: notes/`); classify it there, never around it. The link check reads the same manifest: a shipped `.md` that links into an exclude prefix, or writes one out at a path boundary, fails with `file:line`, except the lines `EXCLUSION_RULE_SITES` names because they state the rule. Non-markdown config is not scanned.
- **Every gate runs on the tree, in order; the first failure stops the run.** `paths` (the link check), `gitleaks` (the image `GITLEAKS_IMAGE` pins by digest, the tree mounted read-only, findings redacted; Docker is required; the tree's own `.github/gitleaks.toml` is the allowlist when it ships one, the same file CI's diff scan reads, and every workflow that runs gitleaks pins the same image, which a test holds), `notes` (`checkReleases` for `v<version>` over the tree's notes files and a read of the public repo's tags, which places nothing because `release.yml` places the tag; a repo that does not answer is no releases in a dry run and a refusal in a publish), `build` (`pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm -r typecheck`, `pnpm -C tools/categorizer test`). The build runs in a temp copy of the tree committed as a one-commit repository, with `MERGEBRIEF_BASELINE_BASE=HEAD`, because `check:baselines` needs a merge base; the copy is deleted after, so `--out` never holds build output. Tools spawn through `CommandRunner` (`src/logic/command-runner.ts`), so the gates are tested against a fake; one test runs the real scanner and skips without Docker. Each verdict prints as `gate <name>: ok|FAILED, ...` on stdout as it lands; the tools' own output goes to stderr.
- **Own version grammar.** `X.Y.Z` or `X.Y.Z-rc.N`, no leading zeros, optional `v`. Narrower on purpose than persistence's `parseSemver`, which drops any suffix; a candidate sorts before its release here.
- **`src/main.ts` is the only composition root**: argv, the repo root (resolved from the file's location) and the environment the command runner passes on enter there.

## Verification

```sh
pnpm -C tools/release test          # temp trees, one per refusal
pnpm check:releases                 # the gate over docs/releases
pnpm release patch --dry-run        # the tag it would write; refuses off main or without the notes file
pnpm release:export --version 0.1.0 --source origin/main --dry-run --out /tmp/export   # the public tree and its link check
pnpm -C tools/release version-json v0.1.0 --out /tmp/version.json && pnpm -C tools/release release-body v0.1.0 --out /tmp/body.md
pnpm -C tools/release stamp 0.1.0 && pnpm -C apps/cli build && pnpm -C tools/release prune-manifest && git diff --stat && git checkout -- apps/cli/package.json docker-compose.yml docker-compose.external-db.yml
```
